# 节点级 skill 路由

改代码之前、派发之前、验收之前、卡住的时候——**先认出你站在哪个节点**，再看它归口到哪个 skill。没有归口表的时候，skill 读不读得到取决于运气。

## 三步

1. **认出节点。** 你现在要判断的是「这属于哪个项目」「这一步该谁做」「测试红了怎么办」——在 `nodes.md` 的 29 行里找到对应那一行。找不到说明你在做的事不属于本工作区流程，直接做，不用往下走。
2. **看归口。** `skill:名字` 就去打开那个 `SKILL.md`（`~/.agents/skills/<名>/SKILL.md` 或 `.agents/skills/<名>/SKILL.md`），**真的读完**，并在计划或回复里写一句「它改变了什么」——写不出来就是没读。`action:命令` 就把那条命令跑掉，贴输出。
3. **兜底。** 归口 skill 读不到、或读完仍给不出结论，用该行的「兜底动作」，不要自己发明方法，也不要换个名字假装用过。

## 按角色进

| 你是 | 先读 | 第一条动作 |
| --- | --- | --- |
| 协调会话 | `roles.md` §一 | `python tools/work_gate.py --list`，再决定开不开单 |
| 执行会话 | `roles.md` §二 | 取自己的 `session_id` → `bind_session` → 状态 `running` 后才动文件 |
| 验收会话 | `roles.md` §三 | 确认自己没参与过这张单，再逐条对条件跑命令 |

## 装了什么、没接什么

`installed-skills.md` 是套件自带 skill 的处置表：要么接到某个节点，要么写明「明确不接」并指出它属于哪个项目面。
新增一个 skill 后在那张表加一行、并在 `nodes.md` 里补归口，避免「装了但没接」的静默失效。

`gaps.md` 是没有 skill 可归口的 7 个节点：兜底动作 + 这轮不新建 skill 的理由。**不要为了表好看编一个 skill 名顶上。**

## 校验

本套件不附带 `check_routing.py` 这类校验脚本。原因是它们校验的是「某台机器上已装的全部 skill」——同一个脚本在原工作区能过，换一台装了别的 skill 的机器就会报「已装未处置」，容易被误读成安装失败。

在这份套件里，路由表本身（`nodes.md` / `roles.md` / `gaps.md` / `installed-skills.md`）就是交付物：它告诉你每个判断节点该打开哪个 skill。装了新的 skill 之后，照着 `installed-skills.md` 的维护规则加一行、并在 `nodes.md` 里补归口即可。

## 边界

本目录只保证「每个节点有归口、归口真实存在、已装的都处置过」。它**不保证**某个会话照图索骥就把事做对了——那要靠 `verification-before-completion` 和独立验收。
本目录不放方法，方法在各 skill 里。要补方法，按 N25 走 `writing-skills`，不要往这里加长文。
