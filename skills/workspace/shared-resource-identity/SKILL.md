# 共用可变资源的身份

一台设备、一个部署、一个共享库、一个共享目录，都不是「我的环境」：它们**多人共用，内容随时会被换掉**。在上面量出来的尺寸、拍下来的图、跑出来的数，只对**当时那个身份**成立。身份没记下来，证据就是一张没有出处的图——别人无法判断它来自哪一份构建，你自己过两天也判断不出来。

本 skill 只管一件事：**让每条证据都说得出「在身份为 X 的产物上得的」。** 口径的权威文本在 `PRD/PRD-012-共用资源的身份与占用.md`；这里写的是照着做的一步步。

## 一、四类资源与它们的身份出口

| 资源 | 身份是什么（一句话） | 读法（采集前跑一次） | 读到什么算身份不符 |
| --- | --- | --- | --- |
| 真机 / 平板 / 模拟器 | 设备序列号 + 屏上那一版的 package 名与 versionName | `hdc list targets`；`hdc shell bm dump -n <bundle>` 取 `versionName` / `versionCode`（Android 侧是 `adb shell dumpsys package <pkg>`） | 序列号不是派单里说的那一台；`versionName` 与本次刚装进设备的包对不上 |
| 部署环境 | 这次部署的 deployment id 与时间（或入口上那一行构建信息） | 部署工具的回执里那条 id 与时间；有版本端点就跑 `curl -s <入口>/version.json` | 回执的 id / 时间早于本次构建；入口上那一行对不上本次 commit |
| 共享数据库 | 绝对路径 + schema 版本（`PRAGMA user_version`） | `python -c "import sqlite3,sys;print(sqlite3.connect(sys.argv[1]).execute('PRAGMA user_version').fetchone()[0])" <绝对路径>` | 路径解析到的不是登记的库；`user_version` 与文档写的 schema 不一致 |
| 共享目录 / 工作树 | 绝对路径 + 分支名 + `git rev-parse HEAD` | `git -C <目录> rev-parse --abbrev-ref HEAD`；`git -C <目录> rev-parse HEAD`；`git -C <目录> status --porcelain` | 分支不是本工单那条；head 不是提交时说好的那一支；有别人未提交的改动 |

**归成一句话写进证据**：`<资源类型> / <身份值> / <读它的命令与输出>`。三样缺一样，这条证据就不可判。

**读不出身份怎么办**：写「本次身份未取到」，并把这条证据标成未验证。不许拿「应该是那台吧」「我记得装的是这版」补位——那正是这类误判的开头。

## 二、采集前后各读一次

采集包括：截图、拍视频、量尺寸、跑用例、跑脚本、读库、量接口耗时。凡是「结果会被别人换掉的东西影响」的动作，都按三步走：

1. **采集前读身份。** 把上表那一行命令跑一次，输出原样留在证据里（不是记账，是截图/贴输出）。
2. **采集时不做身份以外的事。** 采集期间不重装、不切分支、不部署、不改库——中途换掉身份，前后两次读到的当然是同一个值，但它已经不是你取证时的那个身份了。
3. **采集后当场再读一次。** 两次读到的值逐字相同，这条证据才算「在身份 X 上得的」；不同就是身份变过，进第三节。

为什么是「前后各一次」而不是「开始前一次」：并行会话重装包、切分支、重新部署都不需要经过你。中间那段时间没有任何东西替你看着它。

## 三、身份变了：证据作废，标未验

以下四种都算**证据作废**，不许留成「已验证」：

| 情形 | 说明 | 怎么办 |
| --- | --- | --- |
| 采集后读到的身份与采集前不同 | 设备被重装、分支被切、库被改、部署被换 | 这条证据作废，重采集；作废那一条在记录里留着并写明为什么作废，不要删掉假装没采过 |
| 设备上是别人的包 | `versionName` 对不上本次构建（并行会话也在同一台设备上装包时最常见） | **停手，先不采集。** 已采的图全部作废；要拿回设备就重装自己那份并重读身份；重装会毁掉别人手工做的登录态或数据时，先问人，不许直接 `uninstall` |
| 采集前后都没读身份 | 证据里没有身份值 | 标「未验证（缺身份）」，不许事后补一个身份值上去 |
| 用模拟器 / Previewer 的画面代替目标设备 | 两者渲染管线不同，密度、玻璃材质、字体都可能不一样 | 只能当参考图，证据里写明「非目标设备」，不计入验收 |

**一条硬规矩**：身份不符的那些数不要「顺手清掉」。作废是记录，不是删除——删掉之后没人分得清「没量过」和「量了不算」。

## 四、占用与归还

共用的东西用之前先登记，用完**恢复原状**：

| 资源 | 占用登记写什么 | 归还清单 |
| --- | --- | --- |
| 真机 / 平板 | 序列号、占用前后各一次 `versionName`、开始时间 | 装回占用前那一版（记下它的 `versionName`）；只有占用前设备上没有登录态与数据时才允许 `uninstall` |
| 部署环境 | deployment id、入口、开始时间 | 回滚到上一个部署，或明确写下「留在入口上的是哪一版、谁继续用」 |
| 共享数据库 | 绝对路径、`user_version`、要改的表与行范围、开始时间 | 取证走**副本**（`cp <库> .data/<工单号>-evidence-copy.sqlite3`）；改过的行还原、连接关掉、临时表删掉 |
| 共享目录 / 工作树 | 绝对路径、分支、head、开始时间 | `git status --porcelain` 干净、不留临时文件、不切主检出的分支、用完 `git worktree remove` |

**30 分钟门槛，两边各一条。**

- **占用人**：连续 30 分钟没有新的取证动作，就当作闲置。要么立刻归还，要么在占用登记里写清「还要多久、下一个动作是什么」——只写「还在用」不算。
- **排队的人**：等满 30 分钟还没拿到，就发消息问人（工作区流程内走 `ask_ticket` 落库并结束本轮）。不许自己抢：重装别人正在用的包、切别人工作树里的分支、改共享库里别人正要提交的行，都算抢。

## 五、最容易漏的四处

| 漏法 | 会出什么事 | 检查 |
| --- | --- | --- |
| 只写「真机截图」就交 | 验收会话无法判断那张图来自哪份构建，等于没证据 | 证据里搜 `<资源类型> / <身份值> / <命令>` 三样齐不齐 |
| 只在开始时读一次 | 中途被并行会话换掉，图与身份对不上却看不出来 | 采集后再读一次，两次值逐字相同 |
| 拿别人的登录态当自己的环境 | 状态页、首页数据看着对，其实是另一个账号 / 另一份包 | 身份里加上包名与 `versionName`，与本次构建对 |
| 占完不归还 | 下一个会话装了包、量了屏，结论却是别人的构建 | 归还清单逐条打勾，`git status` 干净 |

## 六、交付前自检

```bash
# 1. 证据里每条都带身份三元组（把 <证据文件> 换成实际路径）
grep -c "身份" <证据文件>

# 2. 采集前与采集后各一次读身份，都贴在证据里
grep -c "采集前\|采集后" <证据文件>
```

两条都非零，并逐条对着看：身份值是真的读出来的，不是补的。
