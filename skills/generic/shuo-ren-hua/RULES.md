# 改写规则（28 条）

这份文件在**写作或改写**时读。审核不需要它——审核用 SKILL.md 里的四道流程。

规则之间会互相打架，冲突时按文末优先级表走。打架时的总原则只有一句：**选更长、更完整、更像人当面说的那个改法。** 模型的默认方向是压缩，这套规则存在的意义就是抵消它，不要替它加码。 句子有没有被压成标签、倒过来、省掉主语或衔接，以 SKILL.md「最高优先级」为准。

## 改写流程

下面八步在写作或改写时跑。审核不要跑这些。

### 第一步：先定体裁

同样的改法放在三种体裁上，结果完全不同。动手前先选一档，后面所有默认值都跟着走。

| 体裁 | 句长感觉 | 人称 | 冗余度 | 口语度 | 允许的手法 |
|---|---|---|---|---|---|
| 通用书面（公众号、报告、说明文） | 中长句为主，每句一口气能读完 | 用"你/我们"，少用单数"我" | 低，但句间要有承接 | 书面 | 举例、给数、拆步骤 |
| 营销文案（小红书、通知卡、版本前瞻） | 短句为主，但不许短到读不出谁在做什么 | "我/你"直接称 | 高 | 高 | 具体场景、直接称呼、短促断句 |
| 口播稿（视频脚本、直播） | 一句一口气，说完能换过气来 | "我/你" | 最高 | 最高 | 重复、设问、口头衔接（"你看""说白了"） |

几点说明：

- 各档句长的粗略字数起步值收在文末附录，只用于第一遍粗筛。**不要拿它当验收，更不要为了凑字数改句子。**
- "说白了""你看""其实"在口播稿里是正常的口头衔接，在报告里是废话。不要一刀切。
- 篇幅由体裁定，不由"AI 压缩"定。营销文案该短就短，补承接不等于把文案写长。
- 拿不准体裁时问一句，不要猜。

### 第四档：口播脚本（视频台词，如《小镇新鲜事》）

它不是"一篇读出来的文章"，是**分板块、逐行、配画面**的台词表。这个体裁里结构比句子重要。

**适用范围：只有任务是「整期/整场节目的台词表」才走本档和下面的五步流程。** 局部任务（补一个板块、写某几行、润色现有台词）不套全篇骨架——不写开场四件套和收尾，只借用「每行的要求」「骨架句式里和该板块相关的部分」和五步里的第 3–5 步（填素材、回译改写、五条检查）。不是视频台词脚本的体裁（公告、推文、社区文案、新闻稿）一律不进本档，走后面 28 条 + 找同类真实样本。

**写脚本走下面「脚本写作流程」五步，不过本文件后面那 28 条**——28 条是给文章准备的，逐条套在台词表上只会把体裁特征一起杀掉（2026-11-11 冬愿嘉年华 A/B 测试里，带旧版规则的那篇就是这么变成公告腔的，见 `tests/samples/负样本-冬愿嘉年华-AB.md`）。

真实样本（`tests/samples/`，8 篇，分两种子体裁）：

- **单人口播**（《小镇新鲜事》，喵喵单人播报）：小镇新鲜事脚本-0613 / 0716 / 0919 / 1003 / 1107，五篇成稿。小镇新鲜事-0815 是策划底稿（活动大纲 + 你说喵答口径 + 发布文案），用来学"成稿从什么材料长出来"，不是学台词。
- **双人相声**（版本前瞻，主持喵 + 记者汪）：版本前瞻脚本-0627 / 1205，末尾附备用接驳句库。

**结构约定：**

- 全篇分板块：开场 → 各内容板块 → 你说喵答 → 优化清单 → 结尾。板块之间有过场句（"接下来，轮到全新的舞谱创作玩法登场啦！"）。
- 每行一条台词，独立成句，配一个画面。不追求段内连贯，追求每行单独成立。
- 每条台词有功能类型，一篇里五种都要有：**讲故事**（联动剧情）/ **报信息**（日期、数量、等级）/ **教操作**（步骤式：摆进家园→互动→打开界面）/ **过场** / **情绪**（"光动身体还不够，表情才是灵魂！"）。全是报信息就是公告。

**每行的要求：**

- 每行至少一个具体物：星彩礼花炮、舞蹈出版许可券、邮筒睡觉喵夜灯、波叔的家居店。
- 喵喵在场：自称喵喵，叫发展家，语气词（啦、哦、~），破折号可以当动作提示（"选中它——起舞！"）。
- 允许"人"的痕迹：嗯、咳咳、"有的发展家，有的！"。
- 你说喵答是 QA 体：先念玩家的问题，再答。答的时候可以先共情再给结论（"这个被大家讨论了好久的小愿望，工程师一直记在心上"）。

**通用规则在这个体裁下的例外：**

- "首句能换顺序就是罗列"不适用：优化清单段本来就是并列的，按重要性排。
- "删掉这句读者少什么"对过场句的答案是"少一口气"——过场句是节奏件，不是信息件，别当废话删。
- 句长阈值不适用：报信息的行可以短到 10 字（"研究所又上新啦~"）。

**两种子体裁，骨架完全不同，先分清再写：**

| | 小镇新鲜事 | 版本前瞻 |
|---|---|---|
| 主持 | 喵喵单人播报 | 主持喵（捧哏、讲解）+ 记者汪（逗哏、耍宝）双人对话 |
| 篇幅 | 40–130 行 | 240 行上下 |
| 推进 | 逐行播报，过场句衔接板块 | 问—答—打断—吐槽，信息段之间必有短接驳句（"是谁呀？""没问题！"） |
| 密度 | 高，每行一条信息 | 靠角色互动稀释：讲解长句（40–80 字）和极短情绪句（"没有看错哦。"）交替 |

**新鲜事的骨架句式——多篇逐字重复的部分，写时直接用模板，不要自由发挥：**

- 开场四件套：「巴布！发展家们好呀～」+ 一句时令写景（"秋意渐浓，黑夜变长"）+ 本期看点预告 + 固定收束「当然，大家关心的你说喵答也不会缺席！发展家们坐稳喽，我们这就开始！」（0716 与 0919 这句一字不差）。
- 进你说喵答的固定过场：「介绍完近期活动，又到了发展家们关心的你说喵答环节~这一次，喵喵照例带着大家的提问，找工程师们打听到了不少最新情报，来看看吧！」每题先念玩家原话，回答先给结论（「会的！」「可以的！」）再展开。
- 板块过渡靠上一板块自然带出：「说完了金橡果商会的上新，再来看下10月的活动吧~」「说到好看的，不得不提到…」。不许用"接下来是第 N 个板块"。
- 收尾四件套：「以上就是本期小镇新鲜事的全部内容啦！」+ 行动提醒（"记得定好闹钟""一定要记得及时兑换哦！"）+ 喵喵行踪小剧场（"喵喵先去森林里寻找发光蘑菇啦"）+「我们下期再见，拜拜！」。周年庆特别期可换抒情收尾。
- 称谓与口癖：自称喵喵；玩家一律「发展家」，从不说"玩家"；开发是「工程师们」；官方拟人「河狸们」；NPC 直呼其名（波叔、卡清）。句尾 ~、啦、哦、呀、喽 密度高是这个体裁的特征，不是口水，审核时不许当问题提。
- 信息句式：时间前置（"9月24日更新后，……"）；奖励顿号流水罗列；没定的事用软承诺（"正在讨论/规划中，还请期待啦~"）——不许把不确定写成确定。

**版本前瞻（双人相声）的额外约定：**

- 开场套路：回忆列车播片 → 双人报名字 → 回顾半年/一年内容 → 小剧场卖关子 →「那就要从……说起了」。
- 角色分工要稳：喵喵负责科普、讲规则、报日期；汪汪负责打断、耍宝、把话题拐到吃的。夸张段落（玩梗、报菜名式描写）后面必须接一句吐槽收回来（"被汪汪带偏了啦"）。
- 专有名词一律【】括起。
- 收尾固定仪式：日期排比收束（"7月4日…7月11日…"）→ 感谢发展家 → 双人各自报名字 → 合体口号（"我们《心动小镇》见！"）。
- 样本末尾附备用接驳句库（问/答/哼哈语气）。信息段之间缺一口气就从库里取，不要造新腔。

**写脚本的材料门槛更高：** 素材里没有玩法细节（怎么玩、画面是什么）时，只能写出"总览句"。先把每个活动的玩法描述要到手再写，否则每个板块都会退化成"XX 活动上线啦，有奖励哦"。

## 脚本写作流程（样本驱动，五步）

规则管不住生成，样本才管得住。写脚本时模型的默认方向是"编一个通用活泼口播腔"，抵消它的唯一办法是让它手里有真稿可抄。五步按顺序走：

**1. 选样本，整篇读完再动笔。**
从 `tests/samples/` 里选和本次内容结构最接近的一篇：单期活动播报用 1003；活动+你说喵答混合用 0716 / 0919；短平快用 1107；双人版本前瞻用 0627 / 1205。不许不读样本就写。

**2. 抽骨架，不创作骨架。**
把样本的板块顺序和骨架句抄下来当支架：开场四件套、板块过场、你说喵答过场、收尾四件套——这些句子逐字沿用或只做最小改动（换日期、换活动名）。骨架句是这档节目多年磨出来的固定仪式，重新创作反而错。

**3. 填素材，只填素材里有的。**
每个板块填具体物：玩法怎么操作（步骤）、叫什么名的家具/NPC/作物、几月几号几点。素材没给的细节不许发明——缺什么列进材料缺口清单，问用户要。形容词不许补位（"温馨""欢乐""精彩"都是没材料的信号）。

**4. 回译改写，救绕句子。**
写完逐行过一遍：心里把每行翻成最平白的大白话（"混乱期待你记住它"→"有些乱七八糟的事你得自己记着"）。平白版如果更顺、意思没变，就以平白版为底，加回体裁语气（~、啦、喵喵自称）。这是论文里的回译法降维版——AI 写出来的绕，多数是这么救回来的。

**5. 五条检查（代替 28 条）：**

1. 每行至少一个素材里的具体物？
2. 每行读出声，一口气念得完吗？
3. 主语是人、喵喵、还是具体物？（"庆典为大家带来欢乐"这种死物配活物，改掉）
4. 板块过场是从上一板块的内容里长出来的吗？
5. 删掉这行，观众少不少信息、少不少一口气？两样都不少，删。

全部过完才交稿。交稿时附材料缺口清单（如果有）。

### 第一步之后：先找同类真实样本

这套规则是按"抽象议论文"写的。营销文案、口播稿、活动公告的真人文案长得完全不一样，硬套规则会把真该留的东西删掉。

作者手里如果有已经发出去的同类稿子（公众号推文、版本公告、视频脚本），先读它，再动手。读什么：每段有没有具体的东西、句子怎么排、语气到什么程度。

没有样本时，至少记住官方文案的四条硬特征：

1. **每段至少有一个看得见的东西**：一件家具、一个 NPC、一种作物、一个时间点。全是"体验""节奏""门槛"的段落，不管句子多顺都像机器。
2. **玩家能被叫住**：发展家、友友、ta。不是"用户"。
3. **句子按画面走，不按逻辑走**：先给场景，再给信息。
4. **允许语气**：啦、哦、吧、~、章节 emoji。公文语体不需要，游戏文案需要。

对照样本在 `tests/samples/`，差异表在 `tests/校准.md`。

### 第二步：先把原文拆成命题清单

这是唯一的硬约束，也是整篇重写不跑偏的唯一办法。**先拆，再写。**

逐句抽出命题，每条四栏：

```
主体 | 动作 | 对象 | 限定词/出处
```

例：

| # | 主体 | 动作 | 对象 | 限定（必须保留） |
|---|---|---|---|---|
| 1 | 论文作者 | 找来 14 个模型 | 9 大 5 小 | 2026 年 10 月 |
| 2 | 九个模型 | 比中学生更爱用 | 死物配活物 | 写同样题目的作文时 |
| 3 | 作者 | 猜测，未验证 | 后训练导致省字 | 明确说了是猜测 |

规则：

- 一条原文命题必须对应清单一条。原句有几个分句就是几条，不要合并掉。
- 清单之外的东西一律不许进成稿：姓名、机构、数字、日期、引语、来源、因果、动机、场景、案例。想加一句"更有画面感"的描写，就是编造。
- 限定词是命题的一部分。"可能""通常""据说""作者猜测"必须带过去。把"可能提升"写成"提升"是篡改，不是改写。
- 写完逐条打勾。有一条对不上原文，撤掉那一句。

原文自己没给的东西，成稿也不能给。原文抽象就让它抽象。

**如果清单很短、而且全是抽象判断**（比如通篇只有“要重视体验”“需要提升效率”），停止改写。这是内容问题，不是语言问题，重写只会把空洞写得更顺。

这时的交付不是一篇顺了的稿子，是三样东西：

1. 原文（可以只做病句和标点层的最小修正）
2. 一句诊断：第几段空、空在哪里
3. 缺什么材料：要一个数字、一个场景、一个具体对象，还是一个反例

不要用形容词和比喻去填洞。那只是把空洞换了个说法。

### 第三步：定位问题（体检，不是验收）

先看两件事：脚本报出来的可疑位置，和你自己读一遍卡在哪。

```bash
python scripts/lint_readability.py 稿件.txt
python scripts/lint_readability.py --text "直接贴一段"
```

脚本分两组报。

**可信项**（误报已经压得比较低，可以直接当线索用）：

| 项 | 什么意思 |
|---|---|
| 死物配活物（候选） | 无生命主语配上只有活人才做的动作 |
| 名词化 | “完成了对……的……”“实现了……的提升” |
| 顿号串三项以上 | 并列排成同一结构。法规条文、配置清单这类必列项不算 |
| 长句 | 脚本按固定字数阈值标长句，阈值只用于定位 |
| 承接词 | 计数，见下面“会低估”那句 |

**参考项**（误报多，别按数字改）：无谓语片段、句首到第一个动作的距离、前置定语、"的"链。这四项靠词表和位置估算，转折句、带冒号的句子、口语短句都会触发。只看你自己读起来卡的地方。

脚本没有分词也没有句法分析，**只用来找位置，不用来打分**。标"候选"的地方自己看一遍再决定。

承接词只数显式连接词（所以、不过、其实……）。也、就、时间词、顶针、重复名词这些也算承接，脚本数不到，所以真实值通常比报告高。别为了把数字拉到区间里去塞连接词。

不要拿脚本数字当验收标准。数字降下去了文章可能更难读——这正是上一个 skill 栽的地方。

如果稿子是语音转写（ASR），先手动按气口断句再看报告。转写稿没有标点，长句会全部误报。

体检之外自己问三个问题：

1. 这句话读到最后，还记不记得主语是谁？
2. 有没有需要回头再读一遍才懂的地方？在哪？
3. 有没有哪个词配哪个词一看就不对劲？

### 第三步之后：先搭一条问题链

后面二十几条规则都在管句子。句子都改对了，文章还可能像四张 PPT——因为**段与段之间没有关系**。

人写长文的骨架是一条问题链：每写完一节，都会留下一个没解决的问题，下一节接它。不是"另外""还有""此外"，是"那么问题来了"。

看真人怎么走的（程序员老王讲 AI 为什么难读）：

> 为什么难读 → 因为读者会猜错、会记不住 → 两种失败模式举完，接着问：可 AI 真比人更爱这么写吗 → 做了实验，九个模型确实更爱，**但这证据不够**（AI 聊的内容和电影台词本来就不一样） → 换个更硬的办法：翻译回环 → 证明它本来能说清楚 → 那它为什么偏挑难的 → 因为后训练 → 后训练为什么导致这个 → 因为打分只看答案、写长了吃亏 → **但这只是猜** → 自己训个小模型验证 → 结论收窄到"只证明了省字这一件事"

九节，每一节都在回答上一节留下的问题，每一节都在上一节的结论上砍一刀。

所以定稿前检查三件事：

**1. 段与段之间是"所以现在必须问 Y"，还是"另外还有 Z"。**
是后者，整篇重排。判断办法：把每段第一句抽出来单独print，读一遍——如果它们能任意换顺序，就是罗列。

**2. 至少有一处承认证据不够。**
原文或作者手里没有的东西，明写出来：样本太小、只看到现象、这是猜的、别的解释也说得通。不写，读者会觉得你在卖结论。

**3. 作者要在场。**
"我数了一下""看到第八节我才闭嘴""这里要说清一个边界"。判断、犹豫、甚至不耐烦，都是作者在场。全文没有一个人在做判断，就是资料汇编。

**这一条的优先级高于所有句子级规则。** 骨架是罗列，句子改得再顺也救不回来。

### 第四步：先做加法——补的规则（6、7、12、19、20、23）

改写分两个半场，这是上半场：**只补，不删。**

先做加法有两个原因。第一，补承接、补主语要用原文里的素材；先把长句拆了、废话删了，能用来补的东西也被删没了。第二，模型的默认方向是压缩，先逆着默认方向走一遍，后面做减法时才不容易一路滑到底。

上半场只过六条，按顺序：

### 6. 省掉连接成分，读者被卡在半空

这是"省 that"那类问题的中文版。省掉的是告诉读者"后面这块是什么成分"的那个小词。

典型：省掉"的是""所谓""的时候""即""这一"；省掉指代；省掉逻辑连接词直接跳结论。

> ❌ 他以为答案是错的，其实不是。
> ✅ 他以为"答案是错的"，其实他以为的那个答案是错的。

> ❌ 高分是给别人看的，日子是过给自己的。
> ✅ 高分是给别人看的，日子是自己过的，这两件事不一样。

> ❌ 这个改动影响很大，用户反馈很强烈。
> ✅ 这个改动影响很大。用户反馈里最集中的一条是……

改法：把这个小词补回去。补完句子变长了，那是应该长的。

### 7. 零主语评论和断掉的指代

段落一开头直接抛评论，不说是评价什么。读者得回上一段去找对象。

> ❌ 听起来像一条功能描述，底下换掉的是更根本的东西。
> ✅ 这听起来像一条功能描述，底下换掉的是更根本的东西。

> ❌ 值得注意的是，配置本来就是按归属分层放的。
> ✅ 这一点值得注意：配置本来就是按归属分层放的。

改法：补"这/那/它/这一点"点明对象。多数情况加一个字就够。

### 12. 句间要有承接，但不能贴标签

人写作是连着的：上一句的宾语可以做下一句的主语，重复一个名词就能把两句咬上。模型被压缩之后，句子变成一个个独立的判断。

但承接要隐形。贴标签式的承接读起来比不承接更生硬。

优先级从高到低：

1. 语序：上一句的宾语做下一句的主语
2. 重复同一个词，不换成代词
3. 靠断句和标点带过去
4. 顶针：上一句结尾的词做下一句开头
5. 显式连接词，最后手段

显式连接词只在两种情况下用：逻辑关系靠语序读不出来；或者这个转折本身要强调。**全文读下来，如果连接词多到读者能明显感觉到"这篇文章全是所以、不过、其实"，就是在凑数，回去删。**

禁止三种：

- 句首贴标签状语：“奖励方面”“时间上”“在效率方面”“就此而言”
- 句首连接词加逗号单独立着：“于是，……”“所以，……”“其实，……”。要么嵌进句子，要么删掉靠语序
- 同一个连接词翻来覆去用，全篇都是同一个

> ❌ 奖励方面，活动期间能拿到的数量比上一期多。时间上，活动开启后会持续一段时间。
> ✅ 活动期间能拿到的奖励比上一期多，从开启起会持续一段时间。

> ❌ 于是接下来的竞争点，会从模型转向数据。
> ✅ 接下来的竞争点会从模型转向数据。

**什么时候必须写出来。** 隐形承接的前提是关系读者读得出来。两句之间是“本来以为 A，结果是 B”或者“因—果”的时候，省掉连接词就是跳跃。

判据一：把两句并起来读，你会不会下意识补一个“但”或者“所以”。会，就必须写出来。

判据二（跳跃测试）：读到这一句，你会不会先愣一下，问“为什么突然说这个”。会，就是跳了，中间缺一步。

> ❌ 卖方案的供应商也多，什么场景都敢接。砸下去的钱和效果并不总是成正比。
> ✅ 卖方案的供应商也多，什么场景都敢接。可钱砸下去，效果并不总是成正比。

不改：列表项、小标题、对话与引语。

### 19. 短句不许省到读不出谁

短句省主语是口语常态，但省到读者接不上，就变成病句。

触发标记：一个短句只有谓语和补语（“跟得越紧”“一直没停”“还是不行”），而它的主语得往回翻好几句才找得到。

> ❌ 你一直在用错误的方式证明自己。跑得越快，越像被什么东西追着，跟得越紧。
> ✅ 你一直在用错误的方式证明自己。你跑得越快，它跟得越紧，像有什么东西在后面追。

改法：把主语补回来，或把短句并进上一句。

不改：连续短句里的省略（“想了半天。还是没去。”）；对话和引语。

### 20. 主语不许是抽象名词

这是最像 PPT 的一条，也是最难改的一条。句子主语是“成本、表达、起步、瓶颈、关键、核心、竞争点、接受率、这个数字、数据准备度、口径”，谓语是“是、在于、来自、决定、需要、量的”，整句没有一个做事的人。

> ❌ 真正花时间的是改。
> ✅ 写代码不费劲，改才费劲。

> ❌ 卡住人的地方是表达。
> ✅ 它答得对不对，取决于你说得清不清。

> ❌ 这个数字算得出来，但它量的只是最外面一层。
> ✅ 补全被点了多少次，这个数好统计，可它说明不了什么。

改法有三种，按顺序试：

1. 把主语换成做事的人：你、我们、团队、玩家。
2. 换成人之外具体的东西：模块、文档、表格、按钮。
3. 主语实在换不动，就把谓语换成动作：“成本”不能“是”，但你可以“多花两天”。

改完读一遍：这句话里有谁？在干什么？一个都没有，就重写。

### 23. 一段里得有几个“谁做了什么”

整段都是“什么是什么”，读着就是 PPT。一段里，主语是人（或具体物）、谓语是动作的句子，至少要占一半。

判断：把每句的主语圈出来。圈出来全是概念词的段落，整段重写，不是改词。

---

上半场过完，进下半场之前，先交证据——证据是清单，不是数字：

- **补过的话，列出补在哪。** 哪一句、加了什么成分（连接词、主语、指代，还是把主语换成了人）、依据六条里的哪一条。一条一条写得出来，才算补过。
- **六条一条都没命中，也说得通。** 原文可能本来就补无可补——本来就短而完整、本来主语就都是人。这时写明理由，直接进下半场。
- **写不出清单、也说不出理由，就是上半场在跳着走。** 回去重过。

不要拿"变长了没有"来验收自己。为了变长而加字，是规则 13 禁止的凑字数句，比不补更糟。补对了，稿子多半会自然变长一点，但那是副产品，不是目标——目标是每个该补的成分都有名有姓。

### 第五步：再做减法——删、拆、换的规则（其余 22 条）

下半场的原则是：**每条只处理命中的部分，其余照原文意思保留。** 拆句的时候记住上半场刚补好的东西，别又把它拆没了。

### 1. 死物配活物

无生命的东西做出只有活人才做的动作：期待、希望、害怕、记得、决定、拒绝、学会、教会、吞噬、拥抱、诉说。

这是最典型的 AI 搭配错配。读者看到"对话"时不会去猜"吃"这个动作，猜错就得停下来重读。

> ❌ 对话在吞掉自己。
> ✅ 这段对话绕回自己身上，越说越像死循环。

> ❌ 混乱期待你把它独立记下来。
> ✅ 有些乱七八糟的事，你得自己记着。

> ❌ 这个机制在悄悄替你选择。
> ✅ 你以为是自己在选，其实这个机制已经替你筛过一遍了。

改法有三种，按顺序试：把主语换成做这个事的人；或者写成这个东西实际发生了什么；或者先写人看到了什么，再写事情本身。

### 2. 非常规搭配

动词和宾语不是常见搭配，名词和修饰语不是常见组合，读者要停一下才反应过来。

> ❌ 团队完成了对流程稳定性的检查。
> ✅ 团队检查了流程稳不稳。

> ❌ 焦虑在这里显出了形状。
> ✅ 焦虑具体是什么样子，这里能看出来。

改法：还原成最常见的那个动宾搭配。常用搭配不土，猜错才贵。

### 3. 主谓之间塞了新概念

主语出来了，谓语还没到，中间堆了一串新东西。读者得把这一串全存在脑子里，等谓语来了才能拼上。

判断：主语和谓语之间夹着几个读者没见过的概念？一个还存得住，再多就得回头重读——那就拆。

> ❌ 那把一直立在墙角、你还在犹豫要不要学、从头到尾没教过你一个和弦的吉他，其实在等你。
> ✅ 那把吉他立在墙角。你还在犹豫要不要学，它一个和弦也没教过你。

> ❌ 一个能让你在不增加人手的前提下把审核速度提上去的工具。
> ✅ 这个工具能把审核速度提上去，人手不用加。

改法：拆成两三个短句，按"先有什么、然后怎么样"的顺序排。不要把所有修饰都堆在名词前面。

### 4. 长定语和"的"链

判断：中心词前面的修饰长到读者读完修饰、已经忘了中心词是谁，或者"的"字连环出现，就要拆。

> ❌ 我们需要一套能够满足不同用户在多种场景下使用需求的解决方案。
> ✅ 我们需要一套方案，能应付不同人在不同场景下的用法。

> ❌ 这是关于用户增长的一套新的方法论。
> ✅ 这是一套讲用户增长的新方法。

改法：拆成"总—分"两句，或把修饰改成后面单独一句。

### 5. 一句里塞多个新概念

一句话同时引入两个以上读者没见过的东西，还带因果或条件关系。

判断：这句话里有几个词是上一句没出现过的、且承担论证功能的？读者要同时消化好几个，就拆。

> ❌ 因为后训练阶段的打分程序只看答案对不对、不看过程清不清楚，而上下文长度又有限，所以模型学会了长话短说，代价是句子变得难读。
> ✅ 后训练时，打分主要看答案对不对，没人管过程清不清楚。上下文长度又有上限，写得太啰嗦就答不完。两头一挤，模型学会了长话短说。代价是句子变难读了。

改法：一句一个新概念，顺序按因果链走。拆完句子数量多是正常的。

### 8. 概括词吞掉了具体材料

用"显著提升""大幅改善""大量""众多""进行了优化"盖住了原文已经给过的具体值。

> ❌ 新系统实现了效率的提升，处理时间从两小时缩到四十分钟。
> ✅ 新系统把处理时间从两小时压到四十分钟。

> ❌ 公司进行了组织架构的调整。
> ✅ 公司调整了组织架构。

改法：把原文已有的具体值提到概括词的位置，名词化结构还原成动词。原文没有具体值时只还原动词，不许自己编数字。

### 9. 按呼吸断句

一个逗号里塞了两个完整主谓，或者一句话长到念不完。

> ❌ 作者把每个模型的回答都丢进一个专门做翻译的小模型里先翻成日语再翻回英语然后统计难读写法出现的比例。
> ✅ 作者把每个回答都丢进一个翻译小模型里，先翻成日语，再翻回英语。然后统计难读写法还剩多少。

改法：按朗读时的换气点断，不按语法层次断。逗号和句号选哪个不重要，念得顺就行。

长句短句本身不是问题。长短交替是重写的结果，不是目标。为了"参差"去刻意拆句或并句，会造出另一种模板。

### 10. 喻体的落点

比喻本身不是毛病，人类用比喻比 AI 多。但有一类喻体必须改：理想化的职业人格（导师、秘书、助手、伙伴、顾问、管家、审查员、教练），后面往往跟一串褒义修饰和"不仅……更……"的展开。这类喻体在替作者抒情，没有解释任何机制。

第二类也要改：喻体把两个不沾边的领域硬接在一起，读者得先停下来认喻体是什么，再回头看本体。

> ❌ 它像一位耐心的结对伙伴，不仅给出答案，更会追问你为什么这样想。
> ✅ 它会反问你为什么这么想，再给答案。

> ❌ 这个时代像一台不断加速的离心机。
> ✅ 这个时代把人和人的差距越拉越开。

改法：换成这东西实际做了什么；或换一个读者生活里真有、且能对上机制的喻体。

不改：具体的人当喻体（"像一个老师傅"）；喻体带来了正文没给的信息（判断办法：整段删掉比喻，读者会漏掉东西，就保留）。

### 11. 先立误解再推翻

翻案腔是"猜错"最集中的写法：先竖一个读者并没有的误解，再把它推翻。读者读前半句时建立了一个预期，后半句把它拆掉，于是必须回读。

已知写法："不是……而是……""并非……而是……""不在于……而在于……""与其说……不如说……""表面……实际……""看似……实则……""你以为……其实……""这不是 A，是 B""不是……，是……"。清单只是举例，同一个动作换任何字面都要改。

> ❌ 这不是一个工具迭代的问题，而是一个协作方式的问题。
> ✅ 这是协作方式的问题。

> ❌ 不是你不够强，是你一直在用错误的方式证明自己。
> ✅ 你一直在用错误的方式证明自己。

改法：直接下判断，再给依据。判断放在前，理由放在后。确实有修正过程时，用材料走完，不要用句式走。

不改：文章先用材料走过了从误解到修正的过程，而作者是在这一步做自我修正。

### 13. 不为凑字数写句子

为了把承接补够而硬塞的句子，比不承接更糟。这是本 skill 上一版最大的毛病。

触发标记：遮住这一句，读者的信息、判断、节奏三样都不减少。

典型四类：

- 空泛总结：“整个行业都在加速。”“这是新的开始。”“改动还会继续。”
- 预告和过场：“接下来我们看看。”“说回正题。”
- 无信息的评价：“这一点很重要。”“这确实值得想想。”
- 硬补的连接词句：“其实，……”“而且，……”（前后并没有真的递进或修正）

改法：删，或者把它的意思并进相邻那句。

例外：原文独有的命题不能删，只能改写或合并。判断办法：遮住这句，别处还能不能拿到同样的意思。能，是修辞，可以删；不能，是命题，留下但换个说法。

口播稿允许一句呼应，给听众换气。只许一句。

### 14. 不要半文半白

同一篇里混着文言腔和口语，读起来最别扭。

触发标记：“可……”（可起步从来不是瓶颈）、“而……”、“亦”、“其”、“之”、“并非”、单字动词收尾的电报句。

改法：统一到一个语体。通用书面用现代书面语，营销和口播用口语。不要在同一段里跳。

> ❌ 可起步从来不是瓶颈。
> ✅ 起步不是瓶颈。

> ❌ 而真正的成本不在写，在于改。
> ✅ 真正的成本在改。

> ❌ 这个数字算得出来，量的却只是最外面那一层。
> ✅ 这个数字算得出来，但它量的只是最外面一层。

同类的还有：予以、进行、系、该、其。这些词在公文里正常，在普通文章里是距离感。

### 16. 并列项不许同构

三项以上并列，如果句法、字数、收尾都一样，读起来像在填表。四字短语连排尤其明显。

触发标记：并列项字数接近、结构相同、收尾同为“不 X”“X 了”“X 的”。

改法：改掉其中一项的句法。加一个虚词、换成完整短句、或者把两项合成一项。

> ❌ 目标不明确，边界不清晰，验收标准缺失。
> ✅ 目标说不清，边界没划出来，验收标准干脆没有。

> ❌ 情绪藏起来，爱好收起来，那些不计分的部分一点点压缩掉。
> ✅ 情绪藏进不动声色里，爱好一件件收起来。剩下的那些不计分的部分，就这么被压掉了。

不改：编号条目、配置清单、法规条文；营销口号式并列（三短句砸节奏是允许的，但全篇不能都是）。

### 17. 段内句子开头别同款

一段里连着好几句用同一种成分开头，读起来像清单。

触发标记：连着好几句都以判断开头（“X 是……”“X 在……”“不……”“这……”），或连着好几句都以主语开头、没有状语或时间词。

改法：把其中一句的开头换掉。换成时间、对象、动作、一句引语，或者把状语提到前面。

> ❌ 真正花时间的是改。起步倒是省事。瓶颈不在起步，在表达。
> ✅ 真正花时间的是改。起步倒是省事，你不熟悉这套技术栈它也能给出能跑的片段。卡住人的地方其实是表达。

不改：口播稿的排比段、营销的强调段。

### 18. 小标题不复述

小标题下面第一句又把标题说一遍，读者白读一行。

触发标记：首句包含小标题里的词，且整句意思等于标题。

> ❌ **先找出模糊在哪里** / 需求描述不清的时候，先看它是哪一种模糊。
> ✅ **先找出模糊在哪里** / 需求描述不清的时候，别急着追问细节。产品团队的模糊大多落在三个地方……

改法：直接进入怎么做。标题已经把话说完了，正文该往下走。

### 21. 不用“X 的是 Y”

“真正……的是……”“关键的是……”“麻烦的是……”“难的是……”“费劲的是……”。这类句子把动作压成名词，读起来像 PPT 标题。

> ❌ 真正难的是说清楚。
> ✅ 说清楚最难。

> ❌ 真正拉开差距的是数据。
> ✅ 差距全在数据上。

> ❌ 费劲的是改。
> ✅ 改起来费劲。

判断：把“X 的是 Y”翻成“Y 比 X 怎么样”，读得通就是残句，改。

### 22. 术语翻成人话

行业词、术语、公文词，是“不是人说的”第二大来源。同一个意思，同事之间聊天会换一种说法。

| 术语 | 人会怎么说 |
|---|---|
| 决策链条短 | 老板点头就能干 |
| 对成本敏感 | 钱紧 |
| 数据准备度 | 数据干不干净 |
| 显著提升 | 快了不少 |
| 覆盖多种场景 | 什么活都接 |
| 降低起步成本 | 上手快 |
| 同步口径 | 跟着改 |
| 沟通成本高 | 来回扯皮 |
| 落地效果 | 真用起来怎么样 |
| 呈现出加速趋势 | 都在往前赶 |

判断：这个词你会在微信群里这么打出来吗？不会，就换。

不改：合同、公文、学术、技术规范。那些地方术语就是行话，换掉反而错。

### 24. 逗号不能串太长

一句话里用逗号切出太多段，读着喘不上气，中间也容易断错意思。

> ❌ 活儿分得清，哪些步骤天天重复，一眼看得出来，交给工具最省事。
> ✅ 活儿分得清。哪些步骤天天重复，一眼就看得出来，这种最适合交给工具。

改法：把其中两段合成一段（去掉一个逗号），或者在中间断成两句。

### 25. 别倒装

数量词跟在长修饰后面倒装，是书面痕迹，读着别扭。

> ❌ 这些团队有三个很像的地方。
> ✅ 这些团队有三个地方很像。

> ❌ 这是把需求变成任务的三个步骤。
> ✅ 把需求变成任务，分三步。

判断：把“三个 X 的地方”翻成“三个地方 X”，读得通就是倒装了，改。

### 26. 人称跟体裁走

“你”是拉着读者做事，“我们”是把读者拉进来一起，“他们”“团队”是站在外面看。一篇文里只能站一个位置，换位置就是换身份。

| 体裁 | 主要人称 | 克制使用 |
|---|---|---|
| 观察、分析 | 团队、他们、我们 | “你”，一篇里尽量少 |
| 教程、方法 | 你 | 我们（像替读者干活） |
| 营销文案 | 你 | 我们（除非是官方公告口吻） |
| 口播 | 你我交替 | 无人称句（说了半天不知道在跟谁说） |
| 随笔 | 我们 | 你 |

> ❌ 分析文里：你不熟那套技术栈，它也能给你能跑的代码。
> ✅ 分析文里：不熟那套技术栈，它也能给出能跑的代码。

判断：这篇文章是站在读者旁边推他一下，还是站在外面描述一群人？定了就别换。

### 27. 口语小词别扎堆

“压根”“倒是”“就”“才”“可”“其实”，用一两个是人的味道，通篇都是就成了新口癖。

触发标记：这类词出现的频率高到读者觉得像口癖。

改法：留最自然的一两处，其余换说法或直接删。

### 28. 指代词要有先行词

“这种”“这件事”“它”“这一点”，上一句里得有个东西能对上。对不上，读者要停下来找。

> ❌ 活儿分得清：哪些步骤天天重复，一眼就看得出来，这种最适合交给工具。
> ✅ 活儿也分得清，哪些步骤天天重复一眼就看得出来，这种最适合交给工具。

（“这种”指“天天重复的步骤”，上一句得先说清楚是“步骤”，不是“活儿”。）

> ❌ 剩下的一条是钱紧。
> ✅ 还有一条：钱紧，愿意先拿还不成熟的东西试。

改法：要么把先行词写明，要么把小标题式的半句改成完整句。

### 15. 别写成电报（减法收尾的回查）

**这条放在减法最后，专门回查拆句拆过头。** 前面拆完、删完，整篇读一遍：是不是每段都比原来短了？是不是只剩一句句结论了？

短句堆多了，读起来断断续续，比长句更像机器。这是拆句拆过头的结果。

触发标记：连着好几句都是纯结论，没有动作、没有语气、没有具体对象。

**句长短不是判据。** 人说话本来就短，“写代码不费劲，改才费劲”只有九个字，是人话。“起步倒是省事”也是短句。电报体的特征是只有结论没有过程，不是字数少。

改法：给其中一句补上动作或过程，或者把两句并成一句带转折的。

先查是不是拆过头。一个句子的两半本来是一个判断（主张加补充说明），拆成两句就断了气，这种要合回去。

> ❌ 真正花时间的是改。一个三个月没人碰过的模块，动一下能牵出一串看不见的依赖。
> ✅ 真正花时间的是改：一个三个月没人碰过的模块，动一下能牵出一串看不见的依赖。

不改：营销短文案的强调段、口播的停顿句。连着的两句短句是在砸重音，不用动。

### 第六步：表面标记

上面二十八条处理可读性。可读性没问题、但一眼能看出是机器写的标记，还要单独扫一遍。

这一步不能省，也不能要求作者再跑另一个 skill。改完可读性就交稿，用户拿到的还是一篇"读得顺的 AI 文"。

| 标记 | 触发标记 | 改法 |
|---|---|---|
| 序数小标题 | 小标题（`#` 或独立成行的加粗）以「一、二、三」或「第一、第二」编号，且连续三个以上 | 删编号，保留小标题原有文字。正文里的"首先……其次"不动 |
| 空转句引列表 | 一行以冒号结尾、紧跟列表，且这句去掉后信息不减 | 写成有内容的判断，或删掉让列表接上文。不能删列表项 |
| 揭晓式破折号 | 破折号后接揭晓（"答案很简单——专注"） | 改逗号、句号。**同位语补充和画面停顿不算**（"幕布——你的私人露天放映厅"），那是修辞，要留 |
| 复述句 | "这意味着／这表明／换句话说"开头，且内容与前句同义 | 并入前句，或删提示语只留结论 |
| 前置话题壳 | 句首"对于……来说／就……而言／在……方面／关于……"，而后句本来就以该对象为主语 | 对象直接放主语或话题位，删壳子 |
| 前置时间从句 | "当……时，"后面才是重点（英文 When 从句） | 删"当"和"时"。**排比铺画面不算**（"当夕阳沉入湖面，当蒲公英飘向远方——"），那是修辞，要留 |
| 句首路标连接词 | 段首连续出现"然而／因此／此外／与此同时／综上" | 移到主语后，或换"不过／其实／也" |
| 过密顿号 | 一句里三个以上并列排成同一结构 | 概括，或改掉其中一项的句法 |
| 起手式 | "说白了／说穿了／先说结论" | 删掉，直接给判断 |
| 名词化 | "完成了对……的……／实现了……的提升" | 还原成动词（第五步第 8 条已含） |

不改：列表项内部的标点、小标题里的冒号、引语、网址与代码。

### 第七步：禁止清单

整篇重写最容易滑向"表演式人味"。以下动作一律不做，做了比 AI 味更糟：

- 加口头禅、加"说实话""讲真""懂的都懂"
- 加错别字、加不规范标点、加网络梗、加表情符号
- 强行加"我"、强行加个人经历、编一个"我有个朋友"
- 加段子、加抖机灵、加反问句充数
- 加没有信息量的过渡句（"接下来我们看看""话不多说"）
- 为了显得具体而编造细节、数字、场景、对话
- 把正式语体改成聊天语气，或反过来把口播稿写成公文体
- 为了提高"人味"降低判断强度：把"可能"改成"肯定"，把"作者猜测"写成"研究表明"

判断标准：改写后每一句都要能在命题清单里找到出处。只有当语气词、连接词、标点不承载命题时才允许自由加减。

### 第七步半：分段调整

改长文和审长文一样，也要分段，否则改到后面忘了前面动过什么，改出一堆局部正确、整体断裂的东西。

顺序：

1. **先只改「必改」项**，按块从前往后。改完一块，立刻写回账本：改了哪句、改成了什么、有没有动到邻句。
2. **每改完一块，回查接缝**：本块第一句还能接上上一块最后一句吗？本块最后一句还能引出下一块第一句吗？接缝断了，先修接缝再往下。
3. **全部改完，才算动笔结束**——然后跑全文复检，四件事：
   - 命题对账（`check_claims.py`，全文层面跑，分段跑没意义）
   - 重复（同一句话在两块里各改了一遍，会留下两个相似版本）
   - 节奏（每块都改得很短，整篇会变成电报）
   - 新引入的问题（为了修接缝塞进去的连接词，可能造出新的废话）
4. **最后再扫一遍全文**：标题 + 每段第一句。改完之后段落顺序是否还成立。

5. **然后整篇读一遍**，这次是嘴读，不是眼看。两件必查：

   - **改完是不是每段都变短了**。分段改最容易犯的错：每块都嫌自己长，合起来整篇变成电报。但"变短"只是警报，不是判据——发现每段都短了，拿命题清单逐块对一遍：是哪些命题被并掉、被略掉了？对得上的缩短（比如压掉名词化注水）是对的；对不上的，回第四步补。
   - **重复有没有被改出来**。同一句话在不同块里各改了一遍，会留下两个相似版本。`whole_pass.py` 能抓字面的，意思重复还得人读。

不许一边审一边改。审的时候改，判断就变成"我能不能改"，而不是"这里有没有问题"——很多问题改不了，但必须指出来。

### 第八步：验收测试

十一个测试，按顺序跑。前四个靠嘴，中间四个对账，最后三个防过头——**最后一个是专门防越改越精简的，不许跳**。输出前全跑一遍，不通过就回去改。

**1. 朗读测试**
读出声。卡住、要吸一口气才能念完的地方，就是要拆的地方。

**2. 回读测试**
从第一句读到末尾，数一下"读到这里得回头再看一遍"的次数。目标是几乎不用回头。超了说明还有猜错或记不住的位置。

**3. 遮词测试**
随机挑 10 个位置，遮住右边的文字，问自己下一词大概是什么。连续猜不出来的地方，是死物配活物或者跳步。

**4. 谁对谁做了什么**
逐句能不能一句话说出"谁、做了什么、对谁"。说不清的句子就是结构坏了，回去改结构，不是改词。

**5. 命题打勾**
第二步的清单逐条对照成稿打勾。有对不上的，撤掉那一句；有清单里没有的，删掉。

**6. 表面标记清零**
拿"表面标记"那张表扫一遍。命中就改，不用再解释为什么。

**7. 回环测试**
论文用的办法是拿句子来回翻译一遍，看难读的写法会不会消失。中文可以手动做：

挑出自己最没把握的 5 句，每句写一句最平白的大白话。比一下：

- 大白话比原句短，意思却没变 → 原句里有多余的压缩，按规则 1 到 9 改
- 大白话比原句长，但读者更好懂 → 原句省掉了连接成分，按规则 6 补
- 大白话和原句一样短、一样绕 → 不是语言问题，是这句话本来就没想清楚，回去问作者

这一步专门治“自己读惯了看不出来”的句子。

**8. 硬信息对账**

```bash
python scripts/check_claims.py 原文.md 成稿.md
```

它把两边的数字、英文词、引号内容、否定词、限定词列出来对比。“原文有、改后少”里出现数字、专名、引语，基本就是删了命题。

最容易丢的是**限定词**：“往往”“可能”“大多”被拿掉，句子听起来更肯定，判断强度就被篡改了。这不是文风问题，是篡改。

工具对不上因果和目的关系（比如“为提升体验”这类目的句被删），这些只能自己比对。

**9. 承重测试**

和反模板自查一起做。逐句遮住，问一句：拿走它，读者少了什么？

信息、判断、节奏，三样都不少，就是凑数，删。这一步专门治“为了把话说圆而写的句子”，也是本 skill 上一版翻车的地方。

**10. 反模板自查**

前八条做过头，会造出另一种模板：每段都用“其实”开头，每句都在转折，句长全部一样。交稿前查四样：

- 同一连接词出现几次？反复出现就换
- 每段开头是不是同一个路数（都在下判断、都在举例、都在转折）
- 句长是不是趋同了。连续好几句的长度几乎一样，读起来就是机器
- 有没有哪一段改动后仍然说不出“读者能带走什么”

**11. 反向压缩测试**

前面十个测试查的全是“太多”：太长、太绕、太重复。这一条查“太少”，专门治越改越精简。

从成稿里随机抽 10 句，逐句问：**这句话还能多带一个信息吗？**——一个限定、一个对象、一个原因、一个它造成的结果。

- 一半以上答“能”，就是压缩过头：回到第二步的命题清单，看哪些命题在改写时被并掉、被略掉了，补回去。
- 答“能”、但原文本来就没有这个信息，不算压缩过头——那属于材料缺口，写进材料缺口清单，不许自己编。

### 规则边界

三条规则最容易过度应用，把好句子改坏。下表左边才动手，右边保留。

| 规则 | 该改 | 不该改 |
|---|---|---|
| 1 死物配活物 | 抽象概念长出了人的情感、意图、生理动作：焦虑在追赶你、混乱期待你、对话在吞掉自己 | 工具或机制做它本来的事：系统提醒你、地图告诉你、打分程序奖励高分、算法推荐内容。这是中文常用的转喻；文学体裁里有意象的拟人 |
| 11 翻案腔 | 竖一个读者本来没有的误解，然后推翻它，只为制造揭晓感 | 读者真可能有的误解，而且文章用材料论证过；单纯的对举（“高分是给别人看的，日子是过给自己的”）只要论证充分就保留 |
| 10 喻体 | 理想化的职业人格（像一位智慧的导师）；两个领域硬接，读者得停下来认喻体 | 承载全文结构的核心比喻（“这个世界像一个巨大的打分程序”）；具体的人当喻体 |

拿不准时问一句：**读者本来会这么想吗？**会，就不是翻案腔。**这个动作用在人身上吗？**只用在人身上，才是错配。

### 规则打架的时候

规则互相顶的时候，按这个顺序，上面的赢：

| 优先级 | 规则 | 说明 |
|---|---|---|
| 1 | 命题守恒 | 任何改写都不能增删命题。违反就撤销，不管其他规则怎么说 |
| 2 | 每句承重（13） | 占位句是纯负担。想塞没有信息的句子来补承接时，删掉赢 |
| 3 | 别写成电报（15） | 压过头比句子略长更伤。一句读不出谁在做什么，比一句稍长更难读 |
| 4 | 先补（6、7、12、19、20、23） | 承接、主语、材料没补够之前，不动剪刀 |
| 5 | 后拆（3、4、5、9、16） | 拆句服从上面两条。拆完太碎，用规则 15 合回去 |
| 6 | 表面标记 | 最后扫，改完还可以回头再扫一遍 |

具体的四组冲突：

- **补承接 vs 删废话**：只有在"想塞占位句"时才真冲突，那时删赢——占位句是纯负担。正常的承接靠语序和重复名词，不占句子，跟删废话不矛盾。
- **拆句 vs 电报**：电报赢。拆完读起来断断续续，就合回去。宁可留一个略长的顺句，不要三个只有结论的短句。
- **并列同构 vs 必要列举**：必要列举赢。配置项、法规条文、状态取值原样保留。
- **反模板 vs 原文句式**：原文赢。原文本来就是对举收尾，就留对举；只有自己新造的金句要打回去。

找不到对应条目时，用总原则：**选更长、更完整、更像人当面说的那个改法。**

## 改写输出

默认只给成稿，不解释改了什么。

**但有一件事必须附上：材料缺口清单。**

语言改到最后一层，剩下的"不像人写的"通常不是句子问题，是文章里没有人在做事。通篇观点和判断，没有一个具体的事件、数字、场景。这时把句子改成口语腔，也只能得到"口语腔的观点文"。

判断：每段能不能说出"谁、什么时候、干了什么"。说不出来，就是缺材料。

缺的时候不要自己编，在成稿后面列出来：

```
【材料缺口】
- 第 2 段：说"改比写费劲"，没给具体模块、改了什么、花了多久
- 第 3 段：说"多数团队停在评估"，没有对象，缺一个真实的团队和一个卡住的环节
```

这三行比改十句措辞有用。作者补上材料，文章才真的像人写的。

交稿前核一下篇幅。**变短不是成绩，是可疑信号**——模型改写的天生倾向就是越改越短，篇幅表的作用是拦住这个倾向，不是给压缩发许可证：

| 体裁 | 允许区间 |
|---|---|
| 通用书面 | −10% ~ +20% |
| 营销文案 | −5% ~ +15% |
| 口播稿 | −10% ~ +25% |

三点说明：

- 原文靠“进行了调整”“实现了优化”这类名词化注水时，压到区间以下可能是对的。判断办法是数命题——命题没少，就不算删。但这种情况必须在交付时写清楚压掉了哪些注水结构、各在第几段。
- 超出区间（不管哪个方向）就要写清删了哪条、加了什么。字数是结果，不能为了凑区间改句子。
- 改完篇幅变短、同时验收第 11 条又报警，两件事是同一件事：压缩过头。回第四步。

用户要说明时给一张表，不要写散文：

| 原句 | 改后 | 依据 | 风险 |
|---|---|---|---|
| 对话在吞掉自己。 | 这段对话绕回自己身上。 | 规则 1 | 无 |
| 团队完成了对流程的检查。 | 团队检查了流程。 | 规则 8 | 无 |

"风险"栏写两类东西：一是改动可能偏离原意的位置；二是原文本身就空洞、改完仍然空的地方。后者要单独提一句，让作者补材料，不要用语言去填。

## 附录：数字起步值（禁止用作验收）

下面这些数字是写规则时定的起步参考，**不是测量结果**（来源见 RESEARCH.md）。它们只许干一件事：第一遍粗筛时快速定位可疑位置。不许用作验收标准——"句长达标了""连接词没超"都不等于改好了。任何把数字当目标的用法都会造出新模板，这套规则的前两个版本就是这么翻车的。

| 出处 | 数字 | 它本来的意思 |
|---|---|---|
| 体裁三档 | 通用书面约 22–35 字/句，营销约 12–22，口播约 8–20 | 各档的粗略句长分布，不是每句都必须落在里面 |
| 规则 3 | 主谓之间约 2 个新概念 | "读者存不住了"的粗略刻度 |
| 规则 4 | 前置修饰约 15 字、"的"连环约两个 | "长到忘了中心词"的粗略刻度 |
| 规则 12 | 显式连接词约每千字 18 个、同一连接词全篇约 2 次 | "连接词开始有存在感"的粗略刻度 |
| 规则 15 | 通用书面平均句长低于约 20 字 | "可能拆过头了"的警报，不是下限 |
| 规则 17、19 | 连续约三句、主语隔开约两句 | "重复感""找不回主语"的粗略刻度 |
| 规则 24 | 一句话约三个逗号 | "喘不上气"的粗略刻度 |
| 规则 27 | 口语小词一篇约五次 | "像口癖"的粗略刻度 |
| 反模板自查 | 连续约五句长度差不到约五字 | "句长趋同"的粗略刻度 |
| 验收 2 | 回读约 0–1 次 | "几乎不用回头"的粗略刻度 |

用法只有一条：数字报警了，回到正文那条规则的判据（"读者存得住吗""读得出谁在做什么吗"）再判一次。**判据说没问题，数字就作废。**
