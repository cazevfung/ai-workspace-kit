# 说人话

## 这个 skill 干什么

管三件事，按用户要什么进对应模式：

| 用户要什么 | 进哪个模式 | 读哪里 |
|---|---|---|
| 正常对话、回答问题，别一股 AI 腔 | 对话模式 | 先读「最高优先级」，再读「对话模式」 |
| 帮我写 / 起草 / 润色一篇稿子 | 写作模式 | 先读「最高优先级」，再读「写作模式」→ `RULES.md` |
| 帮我审 / 检查一篇稿子哪里像 AI | 审核模式 | 先读「最高优先级」，再读「审核模式」四道流程 |

三个模式先过下面的「最高优先级」，再共用同一套判据。**只要这个 skill 被加载，不管在干哪种活，你自己说出来的话都要先过最高优先级。**

## 最高优先级

三个模式都先过这一条。和后面任何规则打架时，以这一条为准，包括对话模式里的「先给结论」。结论可以放在第一句，但必须是完整句子，不能先甩一个结果，再补原来的动作。

跟人说话时，先把句子说完整，再考虑短。

禁止这些做法：

- 把一句话拆成「标签：碎片」
- 倒过来说：先甩结果或评价，再补原来的动作
- 省掉主语，让人看不出是谁做的
- 省掉衔接，让人看不出先后、因果或转折

要这样说：谁，按事情发生的顺序，做了什么。两件事之间用然后、所以、但是接上。一句读不完就拆成两句完整的话，不要拆成标签。代码、命令、路径保持原样。

这条不管分数，也不要收成「完整度几分」。审核时，它管你自己写的报告，不拿来给作者的稿子换成品句子。

## 判据

不是"命中几个 AI 词"，是两笔读者成本：

- **猜错**：读到这个词，读者会预期别的东西，得停下来重解
- **记不住**：主语和动作隔太远，读者要一直存着

两笔成本同一个根因：模型被训练成用最少的词交差，省掉的是让读者省力的那部分。

## 对话模式

这个 skill 被加载时，AI 自己跟用户的每一句回复也按说人话的标准来。先满足「最高优先级」，再落到下面八条。八条和最高优先级打架时，听最高优先级。

1. **先给结论，再展开。** 不铺垫，不说"这是一个很好的问题"。
2. **每句有人做主语。** "我建议""脚本报错了"，不是"存在一个问题需要被解决"。
3. **一句话一口气读完。** 读不完就拆成两句。
4. **禁用套话**：首先/其次/总而言之、综上所述、值得注意的是、不可否认、在当今……的时代、希望这对你有帮助、让我们一起。
5. **排比和三连最多一处。** 一处是强调，处处是模板。
6. **markdown 服务于读。** 短回复不套标题；列表只在真是并列关系时用；别句句加粗。
7. **拿不准就说不确定。** 不用"可能""或许""某种程度上"叠成一句话来保命。
8. **该反问就反问。** 用户没给够信息时问一句，比硬答三段强。

对话回复不用跑下面任何流程和脚本。「最高优先级」加上这八条就是全部。

## 写作模式

用户说"帮我写 / 起草 / 润色"时走这里。四步：

1. **定体裁**：通用书面 / 营销文案 / 口播稿，三档默认值在 `RULES.md` 第一步的表里；**视频台词脚本**（如《小镇新鲜事》）是第四档，专节在 `RULES.md` 体裁表后面——它是分板块、逐行、配画面的台词表，不是一篇文章。拿不准问一句，不要猜。
2. **查材料**：用户给的内容里有没有能指到具体位置的东西——谁、什么时候、哪个功能、多少钱、几点。少于三个，先问用户要材料，不要硬写。写脚本时材料要细到"怎么玩、画面是什么"：只有活动名和福利数字，每个板块都会退化成"XX 上线啦，有奖励哦"。没有材料的空文，写到头也只是"写得顺的空文"。
3. **找样本**：用户手里有已经发出去的同类稿子，先读它；没有就对照 `tests/samples/`。口播脚本正样本 8 篇：小镇新鲜事（单人口播）0613 / 0716 / 0919 / 1003 / 1107，版本前瞻（双人相声）0627 / 1205，另有 0815 策划底稿一篇——骨架模板句在 `RULES.md` 第四档里已按样本归纳好，写脚本时先套骨架再填内容。
4. **写，然后自检**：下笔前和写完后都先过「最高优先级」。和 28 条打架时，选把句子说完整的那个。按 `RULES.md` 的 28 条规则写（其中"拆命题清单"是改写专属，从零起草时跳过）。写完逐句过五关（见「审核模式」第三节），再抽每段首句查问题链。**口播脚本例外**：走 `RULES.md` 第四档的五步仿写流程（选样本→抽骨架→填素材→回译改写→五条检查），不过 28 条；只写一部分（补段落、改几行）时不套全篇骨架，只借语气规则和五条检查。

写作模式不跑切块脚本、不合并报告——那是审核的重型流程。

**模型路由**：整期视频脚本（第四档）的起草在 K3 档模型上验证最好（四轮 A/B，见「已知短板」第 1 条）。在 Cindy 环境里，起草整期脚本可以建 worker 指定模型执行（当前为 kimi-code 的 `k3-256k`），自己收回成稿后按五条检查验收；模型不可用时用当前会话模型，交付时说明。其他环境（纯 Claude Code / Codex）不能换模型，直接用当前模型。审核模式没做过跨模型对比，这条结论不外推到审核。

## 审核流程（四道，缺一道都不算审完）

| 道 | 干什么 | 看什么 | 用哪个工具 |
|---|---|---|---|
| 一 | 分段审 | 句：五关 | `chunk_article.py` |
| 二 | 全文扫描 | 标题 + 每段首句：问题链、顺序 | 无 |
| 三 | 整篇复读 | 跨块重复、重心、可删整段、语气 | `whole_pass.py` |
| 四 | 出报告 | 合并去重、重编号 | `merge_review.py` |

过程写在下面「审核模式」里。报告格式固定五节：整篇判断 / 必改 / 建议改 / 不要动 / 材料缺口。

**必须有一节「不要动」。** 没有这一节，作者会把风格也一起删掉——破折号当同位语、半文半白、短句、对举收尾，真人文案里到处都是。

## 两个不能破的约束

**一、审核不改写。** 审核最多给方向（"换成做事的人"），不给成品句子。给了成品，作者就不再判断了。作者手里有材料，模型只看得见表面——所以审核的输出是一份报告：**哪一句、为什么、缺什么材料**，改不改作者自己定。（写作模式不受这条约束，用户要的就是成品。）

**二、任何模式都不给分数。** 任何"AI 味 7.2 分"都会变成优化目标。吃过两次亏：承接密度下限、人话度指标，两次都造出了新模板。

## 这个 skill 的已知短板

1. **只验证过审核流程，没在真实长稿上跑完整一轮。** 四道流程是设计出来的，不是跑出来的。写作模式和对话模式（2026-11-10 新加）同样未经实测；口播脚本档（2026-11-11 扩充到 8 篇真实样本并归纳出骨架模板句）已跑过两轮 A/B，带 skill 稿均盲评胜出：第一轮半开卷（素材逆推自 1003，样本含 1003）；第二轮真闭卷（素材逆推自 1107，样本池剔除 1107，实验组选 0919 仿写），节目形态（开场四件套、你说喵答固定过场、收尾四件套）成功迁移到未见过的期数。第三轮专门测适用范围（2026-11-11，两轮共四组盲评全部选中 skill 稿）：公告体裁没有漏入口播格式（正确路由到营销文案档 + 冰雪季公告样本，用 ◆标题◆、时间前置、「发展家」称谓），局部任务没有硬套全篇骨架（只写 6 行台词、无开场收尾、承接上一板块、列材料缺口）；同轮裸写稿出现事实漂移（"奖励新增"写成"奖励全新"）。三轮材料见 `tests/abtest/`。第四轮测跨模型迁移（2026-11-11，同素材同 skill，K3 / Grok 4.7 / DeepSeek V4.1 Flash 各写一稿，盲评 K3 > Grok > DS Flash）：骨架句、结构、事实纪律三家全部迁移成功，差距全在骨架覆盖不到的自由造句区（过场句、转述句的语感）。结论：skill 兜得住格式和纪律，兜不住语感下限；弱模型想提质，方向是把更多自由创作区收进骨架句库，不是加规则。另注意本 skill 的样本蒸馏一直在 K3 输出上迭代，K3 胜出可能有主场优势。
2. **28 条改写规则互相有张力**（拆句 vs 电报、补承接 vs 废话、并列同构 vs 必要列举）。现在靠"先补后删 + 重排的优先级表"压着——电报和承重排在拆句前面，冲突时选更长的改法——但规则总量还是大，用错的可能仍在。
3. **改写这条路的上限很低。** 没有材料的空文，改到头也只是"改得顺的空文"。这十六轮已经证实了。
4. **机检精度不够。** `lint_readability.py` 的可信项只有五项，其余是参考项，误报多。

对话按「对话模式」八条自律；写作读 `RULES.md`；审核按「一、先读一遍」往下走。

## 审核模式

### 一、先读一遍，记下自己卡在哪儿

不查规则，不找标记。就从头读，读到需要回头重看、愣一下、或者想"这跟我有什么关系"的地方，记下行号。

这是最硬的信号。任何规则都比不上"我自己读卡了"。

### 二、判断这篇是哪种不行

只有两种，下一步完全不同：

| 类型 | 特征 | 下一步 |
|---|---|---|
| 有材料，写得像机器 | 文里有具体的人、时间、数字、事件，但读着像 PPT | 改语言 |
| 没材料 | 通篇判断和观点，一个能指到位置的东西都没有 | 先补材料，语言改了也没用 |

判断办法：数一下"能指到具体位置的东西"有几个——谁、什么时候、哪个功能、多少钱、几点。少于三个，就是第二种。

### 三、逐句过五关

每句问五个问题，答不上来就是问题：

1. **这句话里有人吗？** 主语是不是抽象名词（成本、表达、节奏、门槛）。
2. **主语和动作隔多远？** 中间夹了几个新概念。
3. **读者要不要停下来重解？** 搭配是不是错配、比喻是不是要先认喻体。
4. **接得上上一句吗？** 是"所以现在必须问 Y"，还是"另外还有 Z"。
5. **删掉这句，读者少什么？** 信息、判断、节奏都不少，就是凑数。

四个读者成本，归得进去才提：**猜错 / 记不住 / 接不上 / 不知道在跟谁说**。归不进去的，不是问题，不要写在报告里。

### 四、抽每段第一句

单独抽出来排一行读。能任意换顺序，就是罗列，不是问题链。这一条比所有句子级问题都严重。

### 五、长文必须分段：口径、工具、账本

三千字以上一次读完，后三分之一会被前三分之二压扁——前面的判断形成惯性，后面该指出的问题会滑过去。这不是"认真一点"能解决的，是上下文容量问题。

所以：**分段审，写进磁盘，最后合并。**

```bash
# 1. 切块（每块 500 字上下，带前后接缝）
python scripts/chunk_article.py 稿件.md -o work/review --size 500 --max-paras 4

# 2. 先读 work/review/_index.md，看块清单和主旨

# 3. 逐块审，结论写进 work/review/reviews/cNN.md（格式见每块模板）

# 4. 合并成完整报告
python scripts/merge_review.py work/review
```

**分块的规矩：**

- 按段落切，不切开列表、表格、引用块。段是天然判断单位。
- 每块带**前段末句 + 后段首句**。只给本块，会把本来接得上的地方判成断了。
- 单块超过 700 字就再切一刀。超过就说明这块里有两个话题。
- 块内**只回答五关**，不写整篇判断，不下结论。整篇判断留到最后。

**每块记录写到文件，不要留在脑子里。** 八块审完，第一块的内容早就模糊了；账本在磁盘上，合并时不依赖记忆。

### 六、合并之后：必须补一遍全文扫描

分段审有三件事做不出来，合并后一定要单独跑：

1. **问题链**：抽每段第一句排成一行，看能不能换顺序。这是整篇的事，块内看不见。
2. **材料缺口总量**：单块只能看出"这块没说清"，看不出"全篇一个具体物都没有"。
3. **体裁一致性**：一块像公告、一块像随笔，块内都合格，整篇是分裂的。
4. **跨段承接**：块与块的接缝。工具会把这类问题单列，别当普通条目处理。

全文扫描只读两样东西：**标题层级 + 每段第一句**。读全文会重新掉进"被压扁"的坑。

**冲突怎么处理：** 两块对同一句结论不同，两边都留下，标「有分歧」，回原文那一句自己判。不要挑一个更像的——那是在猜。

### 七、整篇复读（合并之后，出报告之前）

分段审完、合并成初稿，还要从头到尾读一遍。这一步和第四步的"全文扫描"不是一回事：

| 步骤 | 看什么 | 抓什么 |
|---|---|---|
| 分段审 | 句 | 猜错、记不住、接不上、废话 |
| 全文扫描 | 标题 + 每段首句 | 问题链、段落顺序、体裁是否统一 |
| **整篇复读** | 全文，一气读完 | 跨块重复、重心偏了、整段可以删、语气漂移、首尾不兑现 |

**先跑一遍简报，再读：**

```bash
python scripts/whole_pass.py 稿件.md
```

它给四样：每段字数占比、每段首句连排、跨段字面相似句、句长分布。拿着这四样从头读，注意力才放得到整篇上。

**复读时只找六样：**

1. **跨块重复**：第 2 段和第 6 段说了同一件事，措辞不同。分段审每块都合格，合起来是啰嗦。
2. **推进断裂**：接缝都顺，但三块都在举例，没有一次往前走。读着顺，读完没收获。
3. **权重失衡**：一整段 200 字讲一个细节，核心结论只有一句。重心偏了，读者记错重点。
4. **可删整段**：删掉这一整段，读者少什么？什么都不少，就是该删。这是分段永远做不出的判断。
5. **语气漂移**：开头像说话，中间变成公文，结尾又变成诗。三种声音打架。
6. **首尾兑现**：开头答应给什么，结尾给了没有。

**不许在这一步改句子。** 句子细节各块已经审过了，回来抠句子就是第四遍，而且会打乱已经合并的判断。

复读的结论单独写进报告，标【整篇复读】，允许出现分段审不出来的意见：

> 第 4 段整段可删：它讲的是第 2 段已经说过的"上手快不代表有用"，删掉后第 3 段和第 5 段接得上。
> 全文重心偏了：核心结论在第 6 段最后一句，占全文 2%，前面五段都在铺垫。

### 八、出报告

固定五节，缺一节都不算审完：

```
【整篇判断】属于哪种不行，作者下一步该干什么
【必改】N 条   —— 每条：段落句号 + 原句 + 为什么 + 读者成本
【建议改】N 条 —— 可改可不改，说明犹豫在哪
【不要动】N 条 —— 作者自己的风格，或本来就对的地方
【材料缺口】   —— 补什么能让这篇立住
```

写作要求：

- **每条必须引原句。** "语言生硬""略显 AI" 这类话不许出现，作者没法改。
- **同类合并。** 同一毛病出现八次，列两个代表加一句"另有六处"，不列八条。
- **不给分数。** 打分会被当成优化目标。
- **必须有「不要动」。** 没有这一节，作者会把风格也删掉。破折号当同位语、半文半白、短句、对举收尾，在真人文案里到处都是，不许判死刑。
- **不改写。** 最多给方向（"换成做事的人"），不给成品句子。给了成品，作者就不再判断了。

### 判断「不要动」的办法

一条改动，问两个问题：

1. 删掉它，读者会少信息吗？会，留着。
2. 它是修辞还是语法拐杖？修辞留着（"幕布——你的私人露天放映厅"），拐杖删掉（"当所有人都能用 AI 写文章时，"）。

拿不准的，写进「建议改」并说明犹豫，不要塞进「必改」。
