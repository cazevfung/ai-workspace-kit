# 交给 AI 工作区

## 1. 什么时候交接

按顺序问三件事，有一件是「是」就交接：

1. 这件事要不要拆成多步？
2. 要不要交付一个别人能验收的东西？
3. 一轮做不完吗？

**用户明确点名时不要先问。** 他说「找 AI 工作区」「交给工作区帮我规划」「开个工单」这类话，就是已经替你判过了，直接交接。

这条只回答「要不要交给工作区」。「这件事属于哪个项目」是 `project-routing` 的事，两者别混。

### 硬规则

用户在长线任务上点名要交给工作区时，**不许先把活做一半再来交接，也不许拿「我可以自己规划」顶上去**。2026-11-17 凌晨，一个内容会话被用户明确要求两次「找 AI 工作区规划和管理」，两次都没交接，自己把活做完了——失败就是这么发生的。交接之后也不再推进同一件事：收到回执只向用户转述。

## 2. 四步

1. **先写六节交接包并落盘。** 六节结构与必填判据在 `~/.agents/intake/intake.md` §2.1，照它写：用户原话逐字引用（`>` 引用块）／要交付什么／做过什么与为什么不行／硬约束／已确认的事实／未决问题。绑着项目就写进项目的 `交接/<日期>-<主题>.md`，没有绑定项目就写 `{{WORKSPACE}}/.data/intake/<session-id>-<日期>.md`。写完跑 `python tools/intake_gate.py <包的绝对路径>`：非零就是缺节，补齐再发，别带着缺节去发消息。正文不在这里重抄——重抄一份必然分叉。
2. **取自己的标识。** 用 `cindy_helper` 的 `call_tool` 调 `get_current_session_id`，取到什么写什么；不拼、不缩写、不从临时目录名或路径猜。
3. **新建工作区会话，消息只写四行。** 用 `send_to_session`，**不传** `target_session_id`（传了就是投给某个已有会话，不传才是新建），并显式传 `project_path={{WORKSPACE}}`。省略 `project_path` 会继承来源会话的归属，来源没绑项目时新会话也不落地。四行是：要做的事／来源项目与会话标识／交接包绝对路径与「六节齐全，缺节不得接收」／背景以交接包为准、历史可用 `get_chat_history` 核对。
4. **交接后停手。** 收到回执只向用户转述，不再推进同一件事。

## 3. 例外：你已经在里面了

会话的工作目录就是 `{{WORKSPACE}}`（或它的某棵工作树）时，你已经是协调者，**不要向自己派发**——那会撞 `SELF_DISPATCH`。这时该做的是开工单，不是交接。

## 4. 指针

交接协议的正文在 `~/.agents/intake/intake.md`（固定读取路径）。四行消息的完整写法、六节交接包的结构与闸门判据、来源会话没绑项目时落哪儿（迁会话还是另起一条）、交接后不再推进的判据，都在那一份里，不要在这里重抄一份。
