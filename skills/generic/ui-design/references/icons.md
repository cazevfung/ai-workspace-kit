# 图标：只从 Lucide 取

图标是最容易「混着用」的一层：一开始用字符，补几个用 emoji，再从一个图标库抄两个 SVG，三个月后同一屏有三种线宽和三种风格。这一份定死来源、尺寸、描边与着色。

## 1. 唯一来源

| 场景 | 怎么取 |
| --- | --- |
| React 项目 | `import { ChevronRight } from 'lucide-react'` |
| 需要裸 SVG（非 React、ArkUI、内联进 HTML） | `https://unpkg.com/lucide-static@latest/icons/chevron-right.svg` |
| 版本 | `lucide-react` 与 `lucide-static` 的版本号会变；本项目验证过的版本是 `lucide-react 1.77.0`（2026-11-21 查 npm registry）。要写进文档的版本号一律带查询日期，不写「最新版就是 1.77」 |

取用一个图标之前先搜一下官方目录里有没有同义的那一个：`chevron-right` 与 `arrow-right` 不是一回事（前者是「能进去」，后者是「走过去」），选错了文案再对也读着别扭。

## 2. 形状：24 网格、描边 1.75

| 项 | 值 | 为什么 |
| --- | --- | --- |
| 网格 | 24 × 24（`viewBox="0 0 24 24"`） | Lucide 全部图标都在这个网格上画的，换网格等于放弃它的对齐 |
| 填充 | `fill="none"`，只描边 | 开口路径被填成实心块，图标会变成另一张图 |
| 线帽 / 转角 | Round / Round | 圆头与整套的圆角语言一致 |
| 描边 | **1.75**（Lucide 默认是 2，我们统一收窄一档） | 2 在 16px 尺寸下偏重，1.75 在 14–22px 之间都稳定 |
| 缩放 | 描边随尺寸等比缩放（写进 `Icon` 的接口，不写死绝对值） | 绝对描边会让 14px 的图标糊成一团，22px 的又显得细 |

**同一屏出现三种描边宽度就是错。** 判断方法：把图标全选，看 `stroke-width` 有几个值——只能有一个。

## 3. 尺寸按位取

| 位置 | 尺寸 |
| --- | --- |
| 标签旁（文字 + 图标） | 16 |
| 状态点旁（在线 / 执行中 这类词边上的小图标） | 14–16 |
| 行内（正文里的图标） | 18 |
| 按钮里 | 20 |
| 导航（底部三格、rail） | 22 |

同一排里相邻的两个图标用同一档：一个 16 一个 18，看起来像没对齐。

图标尺寸不是热区。按钮里的图标是 20，按钮的热区仍然是 44——把图标做到 44 是另一回事，那叫「用图标当热区」，只有纯图标按钮才这么做，且要配 `aria-label`。

## 4. 颜色走 token

- SVG 里写 `currentColor`（React 里用 className 的 `text-*`），颜色由外层文字色决定。
- **不许在 SVG 里写死浅色 / 深色两套描边**：那样等于绕开 token，主题一切换就有两个来源在争。
- 需要「同一个图标两种颜色」时，放两个元素各染各的，不要在 SVG 里加条件分支。

ArkUI 这类平台用 `Image(svg) + colorFilter` 染色（颜色矩阵取「RGB 全 0、常数偏移 = 目标色、alpha 原样」），不要用 `Shape` + `Path` 自绘：`Path.commands` 的坐标单位是 px 不是 vp，缩放会先缩到左上角一小块。

## 5. 命名

| 项 | 规则 | 例子 |
| --- | --- | --- |
| 文件 | kebab-case，与 Lucide 目录名一致 | `chevron-right.svg` |
| 组件 | PascalCase | `ChevronRight` |
| 资源名（资源系统只收 `[a-zA-Z0-9_]`） | 连字符换下划线 | `ic_lucide_chevron_right.svg` |

**不手改 path 数据。** 需要不同粗细时改 `stroke-width`，需要不同大小改尺寸，不要动路径——改了之后升级 Lucide 会冲突，而且没有任何人能从代码里看出它被改过。

## 6. 什么时候可以不要文字

四个条件**全部满足**才可以只留图标：

1. 图标含义唯一（`chevron-right`、`plus`、`x` 这类；`ellipsis` 勉强，`settings` 不行）；
2. 不产生歧义（同屏里没有第二个长得像的）；
3. 删掉文字后仍有按压态与无障碍名（`aria-label` 或 `accessibilityText`）；
4. 那个字本来不是信息本身（是「名字」而不是「内容」）。

**一个字都不许删的**：状态词（在线 / 执行中 / 离线 / 剩余额度），后果重的动作（停止 / 删除 / 归档 / 确认重发），空态里的下一步按钮（文字就是引导）。

省字不省反馈：删了标签不等于删了按压态。当前格怎么认，要靠指示条或提亮，而不是靠「猜我点的是哪个」。

### 6.1 三种常见组合

| 组合 | 图标 | 间距 | 热区 | 无障碍名 |
| --- | --- | --- | --- | --- |
| 图标 + 文字（主按钮） | 20 | 图标与文字 4 | 高度 44 | 文字本身就是名字 |
| 图标 + 文字（列表行尾随） | 18 | 与文字 8 | 整行 44 以上 | 整行标题 |
| 只有图标（工具栏按钮） | 20 | —— | 44 × 44 | 必须有 `aria-label` / `accessibilityText` |

第一列的顺序就是优先级：**能用文字讲清楚的，就不要只留图标。** 纯图标只在工具栏、状态行这类位置成立，因为那里每个位置的含义是固定的。

## 7. 动画图标

用 animate-ui 的 `AnimateIcon` 包住图标，配触发方式：

| 触发 | 用在 |
| --- | --- |
| `hover` | 指针设备的次级动作（刷新、复制） |
| `tap` | 点了会有结果的按钮（发送、收藏） |
| `inView` | 进入视口时播一次（首屏的强调图标） |
| `loop` | 表示持续状态（进行中的状态点）——**只给状态，不给装饰** |

动的是图标内部部件（箭头转一下、勾弹一下），**不是整块缩放**。整块缩放是按钮的按压反馈，两件事不要叠在同一个元素上。

## 8. 反例

看到任意一条即不合格：

1. 字符图标：`›` `‹` `⋯` `☰` `✓` `✕` `★` `→`。它们在不同字体下大小、基线、粗细都不一样。
2. emoji 当图标（`✅` `⚙️` `📁`）。emoji 在每台机器上长得不一样，也不跟 token 变色。
3. 混用第二套图标库（Font Awesome、Material Icons、iconfont、Bootstrap Icons）。两套的网格与线宽对不上。
4. 同一屏三种描边宽度。
5. SVG 里写死颜色，深浅两套各存一份文件。
6. 用 CSS 画图标（`border` 拼三角、`::before` 画勾）。改一次尺寸就要重新算一遍。
7. 纯图标按钮没有无障碍名。
8. 把状态词删成图标（「执行中」只剩一个转圈的图标）。

## 9. 自检命令

在项目根跑，三条都应该是 0：

```bash
# 1. 字符图标当图标用（HTML 与样式里）
grep -rn "[›‹⋯☰✓✕★→]" --include=*.html --include=*.css --include=*.tsx --include=*.jsx --include=*.vue .

# 2. 混进第二套图标库
grep -rniE "font-?awesome|material-icons|material-symbols|iconfont|bootstrap-icons|ionicons" --include=*.html --include=*.tsx --include=*.jsx --include=*.vue .

# 3. SVG 里写死颜色（应该全是 currentColor 或 none）
grep -rnE "stroke=\"#|fill=\"#" --include=*.svg . | grep -v lucide
```

前两条与 `scripts/check_ui.py` 的 `glyph` / `icon-mix` 规则是同一件事，脚本能一次跑完；第三条脚本不查（SVG 内容是跳过的，它属于资产而不是界面代码），需要单独看一眼。
