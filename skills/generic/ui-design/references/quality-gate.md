# 品质判据：把「不像样」拆成能逐条判的东西

这张表是交付前的最后一道，也是审别人界面时的统一尺子。每条都写「怎么判」和「看到什么算不合格」——只写「要精致」这种话，判不出来。

脚本能量化的（色值、间距、圆角、字号、时长、reduced-motion、字符图标、焦点、图标库）已经进了 `scripts/check_ui.py`，表里标了 `脚本`。剩下的靠看得见的证据：截图、DOM、对比度量值。

## 一，判据表

| 判据 | 怎么判（命令或观察） | 反例（看到什么算不合格） |
| --- | --- | --- |
| 层级只靠字号、字重、留白 | 数这一屏用了几种字号、几种字重；把颜色全换成灰阶再看还读不读得出层级 | 为了分层把卡片加回描边或投影；同一屏出现五档字号；标题和正文只差颜色 |
| 间距都在档上 | `脚本`：`check_ui.py` 的 `space` 规则；或人工数 `padding` / `margin` / `gap` 的值 | `padding: 10px`、`margin-top: 6px`；相邻两层用同一个数字（页面 16、卡片内边距也 16） |
| 圆角不超过三种 | 数这一页用到的圆角档位（`micro` 不参与统计） | 一页出现 `8` / `12` / `18` 这些档外值；卡片和气泡一个样；面板顶角和卡片一样 |
| 色值只有一处定义 | `脚本`：`color` 规则；再 `grep -c "#" 页面文件` 看有没有漏网的 | 页面文件里出现 `#FFFFFF`；深浅两套各写一遍色值；同一个「次要文字」有两处定义 |
| 描边只剩「浮起来的面」 | 数这一页的 1px 描边处数：只该有代码块与浮层；列表看有没有发丝分隔线 | 列表每行一个框；卡片描边 + 投影 + 淡底三件一起上；输入框用 2px 描边代替背景差 |
| 正文对比度 ≥4.5:1、界面元素 ≥3:1、卡片淡底 ≥1.2:1 | 用取色器量：正文 vs 底、图标/边框 vs 底、卡片底 vs 页面底（算法见 §2.1） | 浅灰字压在浅灰底上；卡片底与页面只差 1.05:1；深色下把浅色整体调暗导致文字差值不够 |
| 触控热区 ≥44px（桌面端可降到 32px） | 量可点元素的盒子：`min-height` / `min-width` 或实际渲染盒；纯图标按钮要量到 44 | 图标 20 就给它 20 的热区；行高 18 的紧凑行外扩成 44 导致相邻行热区重叠；桌面端按 32 做实但没写例外条件 |
| 键盘可达且 `:focus-visible` 可见 | `脚本`：`focus` 规则；再用 TAB 走一遍，看焦点框在不在、顺序对不对 | `outline: none` 之后没有任何替代；焦点只在鼠标点击时出现；焦点被动画吃掉 |
| 动效时长都在档上、没有 `transition: all` | `脚本`：`motion` 规则；`npx @animate-ui/cli audit` 看完整清单 | `transition: all 0.2s`；`ease-in` 进场；时长 500ms 的按钮反馈；无限旋转的装饰 |
| 有 `prefers-reduced-motion` 路径 | `脚本`：`reduced-motion` 规则；再手动开系统「减弱动效」走一遍主流程 | 只有 `animation` 没有媒体查询；减弱后状态不生效（内容根本不出现） |
| 图标只有一套、尺寸成档 | `脚本`：`glyph` / `icon-mix` 规则；再数 `stroke-width` 有几个值 | 字符图标 `›`；emoji 当图标；同一屏 16/20/24 三种尺寸；SVG 里写死黑描边 |
| 空态、错误态、加载态三者都在 | 分别断网、给空数据、给慢请求，各看一遍 | 空数据只显示一行灰字；加载用转圈而不是骨架；错误态没有一句人能照做的下一步 |

十二条的顺序不是随意的：前六条决定「像不像」，后六条决定「能不能用」。只过前六条的界面，做 demo 很好看，一上手就露。

### 1.1 触控 44px 的例外条件

44px 与鸿蒙端的 44vp 对齐，宁大不小。桌面端（指针设备、窗口宽度 ≥ 1280）可以降到 **32px**，但要同时满足三条：

1. 该元素在指针设备上只通过点击触发，没有滑动或长按；
2. 相邻可点元素之间的间距 ≥ 8px（热区不会互相覆盖）；
3. 触屏断点（`pointer: coarse`）仍然回到 44px。

例外要写在代码注释里，不要只在评审时说一句。没有这三条的，一律按 44px 判。

紧凑信息行（一行只有 18–20px 高的状态行）是另一种情况：不要给每行外扩热区，那会把相邻行的热区叠在一起、点哪一行没有保证。做法是让行热区等于自己的槽位，再把 44px 放到**块头**（点一次展开整块）。

### 1.2 状态三件事

| 状态 | 要有什么 | 不要有什么 |
| --- | --- | --- |
| 加载（首次） | 骨架块，行高对齐真实行；亮带 1100ms 扫一圈 | 转圈；把已有内容换成灰块（刷新时应保留内容） |
| 空态 | 一句标题 + 一句说明 + **一个**动作按钮 | 一行灰字；没有下一步却叫「空态」（那是错误提示） |
| 错误 | 一句说清发生了什么 + 一句能照做的下一步 + 重试入口 | 只有错误码；把错误塞进 toast 就消失；错误态用红色大面积铺底 |

三者在同一处出现也要有先后：首次加载给骨架、空数据给空态、请求失败给错误（带重试）。三种混着来最糟：加载中显示「还没有数据」，用户会以为数据没了。

## 二，四组判据怎么量

### 2.1 对比度

WCAG 的相对亮度公式（`R`、`G`、`B` 归一化到 0–1）：

```
L = 0.2126 * f(R) + 0.7152 * f(G) + 0.0722 * f(B)
f(c) = c / 12.92                 当 c <= 0.03928
f(c) = ((c + 0.055) / 1.055) ^ 2.4  其余情况
对比度 = (L_亮 + 0.05) / (L_暗 + 0.05)
```

半透明底色（`rgba(...)`）要先合成到它压着的那一层再算，不要直接拿 alpha 值当颜色。合成公式：`结果 = 前景 * alpha + 背景 * (1 - alpha)`。

阈值记三条就够：正文 4.5:1、界面元素（边框、图标、状态点）3:1、卡片淡底与页面 1.2:1。卡片那一条不是 WCAG 的规则，是我们自己的口径——它管的是「边界看不看得出来」。

### 2.2 间距

```bash
python skills/ui-design/scripts/check_ui.py src/           # 档外值一次列完
grep -rnoE "(padding|margin|gap)[a-z-]*: *[0-9]+px" src/ | sort | uniq -c | sort -rn
```

第二条是人工那一半：数一下哪个数字出现最多。如果 `16px` 出现 40 次、`12px` 出现 3 次，那这一页多半只有一层间距，层级是平的。

### 2.3 圆角

数档位而不是数次数：一页里应该只有 2–3 个不同的 `border-radius` 值（`50%` 指圆形，`0` 是没有圆角）。出现第 4 个，先问它是从哪抄来的。

### 2.4 动效

```bash
npx @animate-ui/cli audit
```

输出读法：先看它列的「代价」——动 `width` / `height` 的比动 `transform` 的贵一个数量级；再看「缺 `prefers-reduced-motion`」与 `transition: all` 这两类，它们是脚本也会红的两条；最后按 `motion.md` §5 的「这个元素多常用、它为什么动」逐条留或删。

## 三，评审怎么用

1. **逐条判，不写总体印象。** 十二条各给「过 / 不过」，不过的写清位置（`文件:行号` 或截图上第几屏第几块）。
2. **只列不及格项。** 合格的不用复述，报告里出现「整体不错」这种句子就是没逐条判。
3. **拿证据说话。** 每条不及格配一句怎么复现：跑了哪条命令、量了哪个值、点了哪里。判不出来的按不通过处理，不要「感觉没问题」。
4. **先看脚本，再看剩下的。** `check_ui.py` 退出 0 只说明九类硬指标过了；层级、留白节奏、玻璃、状态三件事仍然要人看。
5. **一次只提一条改法。** 同一处既要不合格又要建议三个方案，执行的人会挑最省事的那个。

### 3.1 报告写成三行一件事

```
[不过] src/pages/Settings.tsx:42  间距不在档上：padding: 10px
  怎么复现：python skills/ui-design/scripts/check_ui.py src/pages/Settings.tsx → 1 处问题
  改法：改成 var(--space-3)（12px），与上面卡片内边距同一档
```

「不过 / 怎么复现 / 改法」三行，不多写。审十二条也就三十几行，执行的人能逐条改完。

## 四，三条「看起来对，其实不对」

这三条是通过了字面检查、但仍然不合格的典型。评审时要专门找它们。

**一，去掉描边了，但把间距也拉平了。** 框是没了，可是每行之间只剩 4px，于是「一组」变成了「一坨」。去框的前提是间距成组：同向 4、跨向 12，比例 1:3 才读得出是一组话。判法：把页面截图缩到 30% 看，还看得出分组吗。

**二，圆角统一了，但层级没了。** 全页都是 16px 圆角，卡片、气泡、按钮一个样，于是「这是一句话」和「这是一块信息」也分不出来。圆角统一不等于只用一种：卡片 16、气泡 20、按钮 pill，三者各自说明自己是什么。判法：把颜色全去掉，看形状还能不能区分卡片、气泡与按钮。

**三，动效加了，但页面还是点一下跳走。** 加了一堆淡入淡出，但次要内容仍然整页跳转，用户还是丢了上下文。动效只解释空间关系，改不了导航结构：该就地展开的地方，动效再多也救不回来。判法：把动效全关掉（开系统减弱动效），操作路径还顺吗。

## 五，交付前十分钟清单

按顺序做，每步都别跳：

1. `python skills/ui-design/scripts/check_ui.py <改动目录>` → 退出 0。
2. 开系统「减弱动效」走一遍主流程 → 功能全在，没有靠动画才生效的状态。
3. TAB 走一遍 → 焦点看得见、顺序合理、没有掉进死角。
4. 缩放窗口到 320px 宽 → 没有横向滚动，按钮没有被压成两个字一行。
5. 断网 / 清空数据 → 错误态与空态都在，各自有下一步。
6. 切到深色 → 没有一片黑、文字与底还够对比、玻璃不发灰。
7. 把截图缩到 30% → 还看得出分组与层级。
8. 逐条过上面那张十二行的表，只记「不过」。
