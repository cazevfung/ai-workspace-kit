## 1. 要解决什么问题

**问题一：进度页只在手机里。** 鸿蒙客户端已经有一份能看的工单进度页：一卡一个项目、每条单一条五步轨道、
谁停在哪一步一眼看得出。但它跟着手机走，人在电脑前干活时看不到——而工单恰恰是在电脑上被派出去、
被执行、被验收的。

**问题二：现有的三种形态都做不到「一直浮在桌面上」。**

| 形态 | 长什么样 | 为什么不是它 |
| --- | --- | --- |
| 浏览器页（`panel/tools/serve.py`，DASH-003 起） | `127.0.0.1` 上的实时页面 | 要开一个浏览器窗口、占整块屏幕、会被别的窗口盖住；它是「去看一眼」的工具，不是常驻读数 |
| Cindy 插件页 | 装在 Cindy 里的页面 | **插件只能活在 Cindy 窗口里**——宿主不提供窗口外的一层，所以它浮不起来，Cindy 最小化就一起没了 |
| 鸿蒙客户端页面 | 手机上的原生页 | 只在手机上，桌面没有 |

**问题三：第四形态没有规格。** 「浮在桌面上」不是把网页缩小：宽度只有 420、一屏只装得下一个项目卡、
没有浏览器地址栏与标签栏、内容区自己滚、还要保住鸿蒙那一套几何与动效。没有一份写死的规格，
做窗口壳的人（下一单）只能靠猜，猜出来的密度和折叠口径一定和手机上不是一回事。

这份 PRD 要做的就是：把「第四形态」定死到能照着做的程度，并交一份能看的样张。

## 2. 边界

| 做 | 不做 |
| --- | --- |
| 定第四形态是什么、不是什么，以及它与前三种形态的差别 | 不做窗口壳：不建 Electron / Tauri / WebView2 工程，不做无边框拖拽、置顶、吸附、开机自启 |
| 定 420×700 的版式映射（每一档尺寸从哪个 token 来） | 不读真数据：不接 `progress-export.json`，不连中心库，样张里全是假数据 |
| 定八条硬指标，每条带反例 | 不做 resolve 的发送链路：不建连接、不发 prompt、不弹确认面板 |
| 定桌面与手机的三处真实差异（宽度、密度、折叠） | 不为了塞更多内容缩小字号、放宽折叠口径 |
| 交自包含样张 HTML 与两张 420×700 的 PNG | 不碰 上游鸿蒙客户端仓库：只读它的 master，不建分支、不改文件 |
| 把五个未决项的理由与默认值写下来 | 不在执行中临时放宽验收条件；规格层面认为不合理的地方在 §8 写清 |

**resolve 这条线的边界（CD-021 查清后补，判据与证据见 `面板仓库的 CD-021 记录`）**：
宿主对**窗口外程序**只公开两种入口——`cindy://` 导航与命令行开关。它们能做的是「把哪条会话叫到前面」
和「在哪个目录打开新建会话」，**没有「替我说这段话」的形态，也没有「在某个目录建一条会话」的接口**；
引擎 CLI 在宿主之外也拿不到 provider 凭证。所以 resolve 的交付就是两件真动作加一句实话：

| 做（都是真的） | 不做（做不到，也不假装） |
| --- | --- |
| 会话还在：请求宿主导航到 `cindy://session/<id>`，并把要交回的那段话放进剪贴板 | 不往会话里发消息（没有这个接口） |
| 没有会话 / 会话已被删：请求宿主 `--open-folder <项目根>` 打开新建会话页，那段话进剪贴板 | 不新建会话（`--open-folder` 只把草稿页打开，正文仍得人发） |
| 结果文案只说可核的事：请求了哪条链接 / 哪个开关、复制了什么 | 不写「已发送」「已交回」「已建好」——那些是完成态 |
| 每一次尝试落一行「发出记录」（`userData/resolve-log.jsonl`） | 不做确认面板（点了直接交回） |

「会话还在不在」读一次宿主的会话库（`sessions` 表，只一条 `SELECT`，`mode=ro`，读完就关）：
有这一行且 `status` 不是 `deleted` 才算在。**读不到就当不知道**，那时照旧可点并预告「会提示找不到」——
不知道不等于没了。

## 3. 第四形态：它是什么

**一句话：一个 420×700、常驻桌面、无边框、内容区自己滚的进度浮窗。** 它借的是鸿蒙进度页那套读法
（一卡一个项目、每单一条五步轨道），不借它的页面外壳（没有导航、没有底栏、没有标题大字号）。

### 3.1 与前三种形态的差别

| 维度 | 浏览器页 | Cindy 插件页 | 鸿蒙页面 | 本形态（浮窗） |
| --- | --- | --- | --- | --- |
| 容器 | 浏览器标签 | Cindy 窗口内 | 手机应用 | 桌面上的独立小窗 |
| 能不能一直都在 | 不能，得有人开着 | 不能，Cindy 最小化就没了 | 手机解锁才在 | 能，常驻置顶 |
| 宽度 | 视口，通常 ≥ 900 | 跟随 Cindy | 竖屏整页（约 360–480） | **固定 420** |
| 高度 | 视口 | 跟随 Cindy | 竖屏整页 | **固定 700** |
| 内容溢出 | 整页滚 | 整页滚 | 整页滚 | **内容区自己滚**，顶部胶囊不跟着走 |
| 输入 | 鼠标 | 鼠标 | 手指 | 鼠标（但热区仍按 44 的手指标） |
| 入口 | 地址 | 插件面板 | 应用图标 | 托盘 / 快捷键（本单不定义） |

### 3.2 这一形态的三条硬约束

1. **不缩放、不重排。** 420 是宽度上限，一屏装不下就滚，不换一套更小的字号，也不把行尾 184 的块挪到第二行。
2. **不带页面外壳。** 没有导航、没有底栏、没有「进度」大标题；顶部只有一条「更新于 HH:MM:SS」的小胶囊。
3. **动效不因为「是桌面」就打折。** 呼吸仍是 800ms、1.0↔1.18，动的仍是圈径。

## 4. 420×700 的版式映射

### 4.1 尺寸表（自外向内）

| 层 | 值 | 来源（鸿蒙 token） | 说明 |
| --- | --- | --- | --- |
| 窗口 | 420 × 700 | 本形态自定 | 固定；不随显示器分辨率变 |
| 页侧留白 | 16 | `SpacingTable.PAGE_SIDE` = `Spacing.lg` | 左右各 16，内容宽 388 |
| 卡与卡 | 16 | `SpacingTable.CARD_GAP` | 与手机一致，不为桌面压缩 |
| 卡内四周 | 20 | `SpacingTable.CARD_INSET` | 内容宽 348 |
| 卡片圆角 | 16 | `AppRadius.card` | 无描边、无投影 |
| 顶部胶囊 | 12/18 字 + 4×10 内边距 | `TypeScale.caption`、`AppRadius.pill` | 显示导出时刻 |
| 项目名 | 16/22 粗体 | `TypeScale.body`、`LineHeight.body` | 卡标题就是项目名 |
| 卡头右侧 | 11/16 | `TypeScale.micro` | 「N 张单」或「● 待验收 N」 |
| 主任务名 | 13/20 粗体，橙 | `TypeScale.footnote`、`LineHeight.footnote` | 多行不裁剪 |
| 工单行 | 12/18 | `TypeScale.caption`、`LineHeight.caption` | 最多两行，超了省略 |
| 合并说明 | 11/16 | `TypeScale.micro` | 只有两种「对不上」才出现 |
| 折叠行 | 12/18，链接色 | `TypeScale.caption` | 最小高 44（`Metrics.TOUCH_MIN`） |
| 行尾块 | **184** | `RowTail.WIDTH` | 轨道 132 + 缝 8 + 图标组 44 |
| 轨道 | **132 × 20** | `Rail.WIDTH` / `Rail.HEIGHT` | 5×20 圆 + 4×8 缝 |
| 圆 | 20 | `Rail.CIRCLE`（`IconSize.lg`） | 整块实心填色 |
| 圈里图标 | 12 | `Rail.NODE`（`IconSize.xxs`） | 镂空（用卡片底色画） |
| 轨道线 | 1 | `Rail.LINE` | 画在圆的中线上，两端各内缩半个圆 |
| 两枚图标 | 20 + 4 + 20 = 44，高 44 | `RowTail.ACTION` / `ACTION_GAP` / `ACTIONS`、`Metrics.TOUCH_MIN` | resolve 在左，进会话在右 |

**对齐是怎么来的（唯一弹性项）。** 一行里有且只有左边那一格文本是弹性的：

```
一行 348 = 文本 156（弹性）+ 缝 8 + 行尾 184（定宽：轨道 132 + 缝 8 + 图标组 44）
轨道起点 x = 16（页侧）+ 20（卡内）+ 156 + 8 = 200
```

短标题、长标题（两行）、池子里没有箭头的那一行，三者的 200 是同一个数（样张实测：所有`.rail`的
`left` 都是 200，`width` 都是 132）。

### 4.2 一屏装多少

样张里第一张项目卡（`cindy-dashboard`，3 个主任务 + 2 条池子单 + 三条折叠行）实测高 **670px**。
减去顶部胶囊区 47px，700 高的窗口里**一屏只装得下一个项目卡，第二张卡要滚才看得到**。

这不是排版没排好，是密度口径不能动：卡内 20、卡间 16、字号按鸿蒙档位，三条都不许为了「多塞一个项目」
改小。要让一屏装两个项目，只有一个办法——把折叠口径放宽（比如主任务从 3 个改成 2 个），
那是 §8 的未决，不是这一单能顺手改的。

### 4.3 数据来源（CD-012 起）

- **两条路，同一套渲染。** `?source=demo`（默认）用内联假数据，单文件、`file://` 能直接看；
  `?source=export` 读电脑上真实导出的那份进度（`progress-export.json`，schemaVersion 3）。
- **传输只走本机只读服务。** 导出物由 `panel/tools/serve.py` 的 `GET /api/feed` 提供（带现有 token），
  页面在 `/window?source=export` 每 3 秒问一次；`file://` 下 fetch 本地 JSON 会被浏览器拦，所以不这么做。
- **按 mtime 触发重读。** 服务端每次只 stat 文件；带 `?since=<fingerprint>` 且 mtime+长度没变时
  只回 `unchanged`，不读文件、不重算模型。文件是原子写，读到的永远是完整的一份。
- **不整页重建。** 页面按「一卡一节点 + 内容指纹」增量替换：哪张卡的数据变了只换那张卡，
  滚动位置与展开状态都留着；读到半截/解析失败时保留上一份数据并加一行提示，不回退假数据、不清屏。
- **折叠口径与鸿蒙一致**：卡内主任务 3 个、单只露 24 小时内动过或在途的、池子 2 条；
  导出物里全部单都在，`show` 标记只决定默认露不露，「展开」后按同一份顺序全给。
- **会话库是第三条只读来源（CD-021）**：每一行要回答「这个 `sessionId` 还去得吗」，读的是导出物
  自报的 `source.sessionsDb`（读不到这个键就退回 `%APPDATA%/Cindy` 下 mtime 最新的 `cindy-*.db`）。
  只一条 `SELECT id, status FROM sessions`，`mode=ro` 打开、读完立刻关连接，不复制库、不做
  checkpoint、不写一个字节；判据是「有这一行且 `status` 不是 `deleted`」。每 2 秒重问一次（导出物
  几分钟才换一份，而会话随时可能被删）；存活表变了才重建卡片。**读不到不算「没了」**：那时箭头
  照画、resolve 照旧交回，文案里预告「若那条会话已被删除，Cindy 会提示找不到」。

### 4.4 顶部胶囊

- 文案固定形状：`更新于 HH:MM:SS`，时间取导出物的 `generatedAt`（秒级）。
- **不写「刚刚刷新」**：它说的是「手里这份快照是什么时候导出的」，不是「几秒前我又读了一次」。
- 胶囊只在真有数据时出现；读不到数据时窗口进错误态，不铺样例卡（沿用鸿蒙 CH-076 的口径）。

## 5. 八条硬指标

每一条都写成「要求 / 怎么落地 / 反例」。反例是验收时要能指着看的东西。

### H1 一卡 = 一个项目，卡内三层

- **要求**：卡片标题 = 项目名；卡内依次是「主任务（橙色粗体 + message 图标）→ 工单行（单号 · 名称，可省略）
  → 每条单自己的五步轨道」。
- **落地**：项目名 16/22 粗体 + 右侧一行计数或状态点；主任务名 13/20 粗体、颜色 `running`，右侧一枚 16 的
  message 图标（同色）；每条单一行 `单号 · 名称`，行尾挂**这条单自己的**轨道——不是卡片级的一条大轨道。
- **反例**：卡片标题写成主任务名；一条轨道管整张卡（九个单停在不同步，一条线说不出来）；
  主任务名用灰色常规字重（读起来像注释）。

### H2 五步：实心圆 + 镂空图标，圆里字形 12

- **要求**：`send / play / upload / check / merge` 五步；圆圈是**整块实心填色**，圈里的图标是**镂空**的
  （用卡片底色画，像从实心圆里挖出来），字形边长 12（圆的 60%）。
- **落地**：圆 20 填 `stepInk()` 的颜色；图标 12 填 `--cut`（= 卡片底色）；圆里不再套第二层圆或框。
- **反例**：描边圆 + 深色实心图标（CH-070 之前的样子）；图标撑到 14–16（圈变成给图标让位）；
  用 alpha 表达「没到」（见 H3 的反例）。

### H3 进行中的整圈按直径呼吸

- **要求**：只有「正在进行中」的那一步呼吸；周期 **800ms**，圈径 **1.0 ↔ 1.18**，动的是 `scale`，
  `opacity` 全程不参与；圈里的图标跟着一起呼吸。
- **落地**：`@keyframes breathe { from { transform: scale(1) } to { transform: scale(1.18) } }`，
  `animation: breathe 800ms ease-in-out infinite alternate`，挂在「圆 + 图标」那一层容器上；
  开「减少动效」时整层动画不构建（不是把时长写成 0）。
- **反例**：用 `opacity` 闪；呼吸只作用于图标而圆不动；把周期缩到 400ms 图更「闪」；
  给完成与没到的圈也注册动画。

### H4 行尾定宽 184

- **要求**：行尾块 `184 = 轨道 132 + 缝 8 + 图标组 44`；左边文本是**唯一**弹性项，所以任意两行的轨道起点
  x 相同——池子行少一枚箭头也不许挪。
- **落地**：`.tail { flex: 0 0 184px }`；`.headline { flex: 1 1 auto; min-width: 0 }`；
  没有目标的图标**留一个同宽的空盒子**占位，而不是把它删掉。
- **反例**：轨道紧跟在文本后面（文本长短不同，起点就跟着跑）；少了箭头就把图标组变窄
  （池子行的 resolve 与别的行错开 24px）。

### H5 两枚图标：各 20 宽、缝 4、高 44，热区 44×44

- **要求**：左 resolve（bug-off），右进会话（右箭头）；视觉 20，可点热区各 **44×44**；两枚热区互不重叠。
- **落地**：`.act { width: 20px; height: 44px }`，`::before` **向外不对称扩**成 44×44——
  左枚 `left: -24px`（热区 316–360），右枚 `right: -24px`（热区 364–408）。两块各 44 宽、中间留 4px 缝，
  互不重叠；扩出去的 24px 各自落在不可点的轨道末段（左）与卡内 20px 内边距加 4px 卡外（右），视觉上什么都看不见。
  没有目标时留空盒子，不画「点了没反应」的图标。
- **反例**：热区只有 20×20（视觉宽就是热区宽）；两枚各以视觉槽为中心往外扩 12（两块重叠 20px）；
  把池子行的箭头画成灰色死按钮。

### H6 橙色只出现在两处（轨道与状态标记上）

- **要求**：`#EA6B17` 在**轨道与状态标记**上只出现在两处——当前步；「需要你出手 / 待验收」的状态点。
  走完的段与圈、已合的单，一律不出现这个橙。
- **落地**：`--running: #EA6B17` 只给 `.node.current .disc`、`.state-dot` 用；走完的段是中性色
  `#999999`，走完的圈是绿 `#2AAE5B`，已合（recorded）的最后一格同样是绿。
- **反例**：走完的轨道段用橙（首屏全是橙，眼睛落不到「在等谁」）；已合的单最后一格还是橙圈在呼吸
  （把「完成」画成「正在做」）。
- **与 H1 的关系**：主任务标题与它的 message 图标是橙色粗体，那是 H1 定的**层级标题色**，
  不参与轨道与状态点着色；两者不混用。

### H7 合并四态

- **要求**：最后一格（合并）按 `mergeState` 分四种，颜色与说明都要对得上：

  | 状态 | 含义 | 圈的颜色 | 行下说明 | resolve |
  | --- | --- | --- | --- | --- |
  | `recorded` | `merges` 有行，且提交真在 master 里 | 绿 `#2AAE5B` | 无 | **不出** |
  | `landed-unrecorded` | 已在 master、库里没记录 | 中性 `textSecondary` | 「已在 master 里，但库里没有合并记录」 | **不出** |
  | `recorded-unlanded` | 库里有记录、提交不在 master | 警告 `#F3A115` | 「库里记了合并，但那个提交不在 master 里」 | 出 |
  | `not-merged` | 两边都没有 | 橙 `#EA6B17`（当前步，呼吸） | 无 | 出 |

- **落地**：四档都是实色，两种「对不上」**不呼吸**（它们不是在走的步骤，是要人看一眼的状态）；
  说明文字 11/16 `textTertiary`，只在后两档出现。
- **为什么 `landed-unrecorded` 不出 resolve（CD-022 落地、CD-021 写进表里）**：这种状态的单**没有下一个
  人要动手**——代码已经在 master 里，差的只是库里那一行合并记录，那是数据侧的账（backfill 或豁免），
  不是会话侧的事。给它一颗 resolve，点下去只会去叫一条早就没了的会话，而浮窗却写「已交回」：
  CD-022 的现场就是这么来的。`recorded-unlanded` 正好相反（要人去查那个提交去哪了），所以按钮留着。
- **反例**：四档都用绿；`landed-unrecorded` 挂着 resolve（人点它只会得到一句「没有悬空的单」）；
  两种「对不上」用同一句说明（补记录与查提交去哪了是完全不同的两件事）。

### H8 折叠口径

- **要求**：三处各一行折叠，**不改顺序**（折叠是过滤/截断，不是另一种排法）：

  | 位置 | 默认露 | 那一行字 |
  | --- | --- | --- |
  | 卡内主任务 | 前 3 个 | `还有 N 个主任务，展开` |
  | 主任务内的单 | 24 小时内动过或**在途**的 | `更早的 N 条，展开` |
  | 池子（未认领） | 2 条 | `展开其余 N 条` |

- **落地**：三处各是一个独立的展开状态，点一处不把另一处也铺开；有单的主任务至少露一行
  （窗口里一张都没有时补最新那张），屏上不出现「只剩一行折叠字的空块」。
- **反例**：为了桌面「多露一点」把主任务从 3 个放宽到 5 个；折叠后重排（先按状态再按时间）；
  点「展开主任务」把池子一起铺出来。

## 7. 桌面与手机的三处真实差异

只有三处，其余一律照手机。

| 差异 | 手机（鸿蒙） | 桌面浮窗（本形态） | 为什么 |
| --- | --- | --- | --- |
| **宽度** | 竖屏整页，随设备 | 固定 420×700，内容区滚，顶部一条「更新于 HH:MM:SS」胶囊 | 浮窗不能抢满屏；固定宽高才能保证密度可预期 |
| **密度** | 卡间 16、卡内 20、按设备字号缩放 | 卡间 16、卡内 20、字号按鸿蒙档位**不缩** | 为了「一屏多塞」而缩字号，等于把「在等谁」变成要用放大镜找 |
| **折叠** | 三条口径（3 / 24h / 2） | **原样保留，不放宽** | 桌面宽度不够放宽的资本：420 只比手机宽一点点，放宽等于把首屏塞满 |

## 8. 未决（理由 + 默认值）

这五条都不当场问人：每条给出理由与默认值，先按默认值做，等人回来再改。

### 未决 #1：两枚图标的热区（已按 44×44 落地，留一条待窗口壳实测）

- **背景**：鸿蒙 CH-081 用 `responseRegion` 把 20 的视觉宽扩到 44。
- **落地**：图标组 44 = 20 + 4 + 20，两枚**全部向卡外方向**扩，不做居中扩：
  - 左枚（resolve）`left: -24px`、`width: 44px` → 热区 **316–360**；
  - 右枚（箭头）`right: -24px`、`width: 44px` → 热区 **364–408**；
  - 两块各 44×44，中间留 4px 缝，**重叠 0px**。
- **为什么不能居中扩**：居中扩会让两块各以视觉槽为中心向两侧各长 12px，两枚之间只剩 4px 缝，
  于是重叠 20px——「各 44」与「不重叠」在 44 宽的组里只有这样（全部往外）能同时成立。
- **扩出去的 24px 落在哪**：
  - 左：316–332 是最后一颗合并圆所在的轨道末段。**轨道本身不可点**，点在那里等于把这张单交回主任务，
    不构成对另一个可点元素的抢点击。
  - 右：384–404 是卡片的右内边距（20px），404–408 落在 `.feed` 的页侧内边距上；两处都没有文字、没有其他可点元素，
    且裁剪链（`.feed` / `.win` 的边界都是 0–420）不会把它裁掉。
- **什么时候回来看**：做窗口壳那一单，用真机鼠标实测这两块 44×44 的手感；
  若确认「点最后一颗合并圆」会误触，再讨论是否把图标组扩到 96（行尾 236，要同时改 H4/H5）。

### 未决 #5：字体

- **默认值**：系统 UI 字体栈（`-apple-system, "Segoe UI", "Microsoft YaHei UI", "Microsoft YaHei", "PingFang SC", …`），

- **已完成项目汇总段**：只有一个占位空位（未决 #2）。

### 待验证（要等真窗口才答得出）

- 420×700 在 125% / 150% 缩放的 Windows 上会不会出现半像素导致的轨道模糊；
- 常驻浮窗上的呼吸动画在后台（窗口被遮挡）时是否该暂停——鸿蒙那边有「切页签重新点火」的现成做法（CH-082），
  桌面要不要照搬，等窗口壳那一单实测。
- **`--open-folder` 这一支没在无人值守时真跑过**（跑一次会把 Cindy 窗口叫到前台）：代码路径读得到，
  但要人工点一次「没有会话的池子行」确认真的切到了那个目录的新建会话页。

### 已知限制

- 样张是**静态假数据**：展开 / 收起行点得动但不会真的换内容（它不是实现，是版式样张）。
- 样张 PNG 由 headless Chrome 以 device scale 1 直接截 420×700 视口得到，不是设计稿导出；套件带四张（展开/折叠 × 浅/深）。
- 会话存活是按会话库那一刻的快照判的：宿主刚把一条会话删掉、浮窗还没问到的那两秒里，箭头仍在。
  这比反过来安全——宁可人点进去看到宿主的「找不到」，也不在会话还在的时候把入口掤掉。
