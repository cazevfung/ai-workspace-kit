## 1. 要解决什么问题

工作区已经有身份链，但它**只覆盖 git 一维**：`head_sha` 说清验收的是哪一棵树，`prd_sha256` 说清依据的是哪一版需求。设备、部署、共享库、共享目录这一维是空的。

空着的代价 2026-11-21 一天里出现了两次，都在鸿蒙项目：

- 一次量出来的屏**不是自己那份构建**——设备上装着并行会话刚装的包，`hdc` 连的是同一台机器，拍下来的图看着没问题，像素量出来的结论却是别人那一版。
- 一次**屏上根本没有这一单刚做的页面**——不是代码没写，是设备上那一版不含它。

两次都不是代码错，也不是判断力不够，是**没有一处要求「先读身份，再取证」**。现在的验收条件照样能写成「在真机上出浅色深色两张图」：它字面通过，却不可能被推翻，因为没人知道那张图来自哪一份构建。

真正需要固化的不是一条提醒，是四件事：**身份从哪读、取证前后各读一次、身份变了证据怎么办、共用的东西怎么还回去**。共用资源还有第二类代价：占着不放。一台设备被一个会话占着，别的会话要么等，要么抢——抢的后果就是上面第一条。

## 2. 边界

- 只管**共用可变资源**这四类：真机/平板/模拟器、部署环境、共享数据库、共享目录/工作树。只读代码、只改本仓库文件时不适用。
- 不替代 `verification-before-completion`（说「做完了」之前要取证）、`ui-design`（界面怎么做）、`ticket-dispatch`（提交与验收的调用顺序）。本 PRD 只管「证据的出处」这一维。
- 不新增宿主能力，不改 `task_center/` 与 `tools/` 的代码：判据靠文档与路由表落地，不做成自动扫描脚本。
- 不动业务项目的任何文件。鸿蒙项目的命令与工单只作举例，改它们要走那个项目的单。
- 不重写 `AGENTS.md` 的七条硬规则。它第四条第 4 点里的节点数同步另开单，见 §8 的 D2。

## 3. 角色分工

- **协调会话**：开单时把「在哪个资源上、以什么身份」写进 `deliverable` 与 `criteria`；验收条件里出现共用资源却没写身份读法的，退回改写，不派发。
- **执行会话**：采集前后各读一次身份，把身份值原样贴进 `evidence`；身份变过就按 §5.3 作废重采，不许把作废的那条改写成已验证。用完按 §5.4 归还。
- **验收会话**：逐条核 `evidence` 里的身份三元组（资源类型 / 身份值 / 读它的命令与输出）。查不到身份值的条件按不通过处理，不许「整体看着对」。
- 三者都不修改本 PRD；要改走 `revise_ticket` 并写明影响哪些在途工单。

## 5. 口径

四段各自能被单独引用：协调写条件时引 §5.1 与 §5.2，执行判断时引 §5.3 与 §5.4。

### 5.1 身份出口：每类资源一句话说清「此刻是谁的、哪一版」

| 资源 | 身份是什么 | 读法（原样跑，输出贴进证据） |
| --- | --- | --- |
| 真机 / 平板 / 模拟器 | 设备序列号 + 屏上那一版的 package 名与 `versionName` / `versionCode` | `hdc list targets`；`hdc shell bm dump -n <bundle>` 取 `versionName` 与 `versionCode`（Android 侧 `adb shell dumpsys package <pkg>`） |
| 部署环境 | 这次部署的 deployment id 与时间，或入口上那一行构建信息 | 部署工具回执里的 id 与时间；有版本端点就跑 `curl -s <入口>/version.json` |
| 共享数据库 | 绝对路径 + schema 版本 | `python -c "import sqlite3,sys;print(sqlite3.connect(sys.argv[1]).execute('PRAGMA user_version').fetchone()[0])" <绝对路径>` |
| 共享目录 / 工作树 | 绝对路径 + 分支名 + `git rev-parse HEAD` | `git -C <目录> rev-parse --abbrev-ref HEAD`；`git -C <目录> rev-parse HEAD`；`git -C <目录> status --porcelain` |

归成一句话写进证据：**`<资源类型> / <身份值> / <读它的命令与输出>`**。三样缺一样，这条证据不可判。

读不出身份的（入口没有版本端点、工具不回 deployment id），写「本次身份未取到」并把该条证据标未验证，不许用「应该是那台」「我记得装的是这版」补位。

### 5.2 取证前先核：先读身份，再采集

**第一步永远是读身份，不是先截图。** 顺序固定成三步：

1. **采集前读一次。** 跑 §5.1 那一行命令，输出原地留在证据里。
2. **采集期间不做换身份的事。** 不重装、不切分支、不重新部署、不改库。中途换过，前后两次读到的固然相同，但那已经不是取证时的那个身份。
3. **采集后当场再读一次。** 两次逐字相同才算「在身份 X 上得的」。

「读到什么算身份不符」逐类写死：

| 资源 | 身份不符 |
| --- | --- |
| 真机 / 平板 | 序列号不是派单里说的那一台；或 `versionName` / `versionCode` 与本次刚装进设备的包对不上 |
| 部署环境 | 回执的 deployment id / 时间早于本次构建；或入口那一行对不上本次 commit |
| 共享数据库 | 路径解析到的不是登记的库；或 `user_version` 与文档写的 schema 不一致 |
| 共享目录 / 工作树 | 分支不是本工单那条；或 head 与提交时说好的那一支不同；或有别人未提交的改动 |

**屏上是别人的包怎么办**（真机这一条被问得最多，单列）：

1. **停手，先不采集。** 已经采下来的图全部作废，不要「先交上去再说」。
2. 要拿回设备就**重装自己那份**，装完回到第 1 步重读身份，两次一致再采集。
3. 重装会毁掉别人的东西时**先问人**：别人手工做的 SSO 登录态、别人正在读的数据，都可能随重装消失。这一步走 `ask_ticket` 落库并结束本轮，不许直接 `uninstall`。
4. 交接给下一个会话时，把「现在设备上是哪一版」写进占用登记，别让它成为下一个人的误判来源。

### 5.3 身份变了：证据作废，标未验

四种都算证据作废，都不许留成「已验证」：

| 情形 | 怎么办 |
| --- | --- |
| 采集后读到的身份与采集前不同 | 这条作废，重采集；作废的那条留在记录里并写原因，不许删掉假装没采过 |
| 设备上是别人的包 | 见 §5.2 的四步；已采图全部作废 |
| 采集前后都没读身份 | 标「未验证（缺身份）」，不许事后补一个身份值 |
| 用模拟器 / Previewer 画面代替目标设备 | 只能当参考图，证据里写明「非目标设备」，不计入验收 |

作废是记录，不是删除：删掉之后没人分得清「没量过」与「量了不算」，下一次同一个误判会原样再来一遍。

### 5.4 占用与归还：30 分钟门槛与归还清单

| 资源 | 占用登记写什么 | 归还清单（恢复到占用前身份） |
| --- | --- | --- |
| 真机 / 平板 | 序列号、占用前后各一次 `versionName`、开始时间 | 装回占用前那一版并记下它的 `versionName`；只有占用前设备上没有登录态与数据时才允许 `uninstall` |
| 部署环境 | deployment id、入口、开始时间 | 回滚到上一个部署，或写明「留在入口上的是哪一版、谁继续用」 |
| 共享数据库 | 绝对路径、`user_version`、要改的表与行范围、开始时间 | 取证走副本（`cp <库> .data/<工单号>-evidence-copy.sqlite3`）；改过的行还原、连接关掉、临时表删掉 |
| 共享目录 / 工作树 | 绝对路径、分支、head、开始时间 | `git status --porcelain` 干净、不留临时文件、不切主检出的分支、用完 `git worktree remove` |

**30 分钟门槛，两边各一条：**

- **占用人**：连续 30 分钟没有新的取证动作，就当作闲置。要么立刻归还，要么在占用登记里写清「还要多久、下一个动作是什么」。只写「还在用」不算。
- **排队的人**：等满 30 分钟还没拿到，就发消息问人（工作区流程内走 `ask_ticket` 落库并结束本轮）。不许自己抢：重装别人正在用的包、切别人工作树里的分支、改共享库里别人正要提交的行，都算抢。

## 7. 不做什么

- 不写扫描脚本、不改 `task_center/` 与 `tools/`：本 PRD 的判据靠文档与路由表落地，靠独立验收对照。
- 不改 `AGENTS.md` 的七条硬规则，也不在本单里改它第四条第 4 点的节点数（见 D2）。
- 不动业务项目的任何文件：鸿蒙项目的命令与工单只作举例。
- 不把「30 分钟」做成定时自动化：门槛是给人当场判的一句话，不是后台任务。
- 不发同步提问卡：需要人拍板的用 `ask_ticket` 落库并结束本轮，无人值守走 `ask_user_question_async` 并给出能直接照做的默认路。
