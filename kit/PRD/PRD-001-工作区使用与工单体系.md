# PRD-001 工作区使用与工单体系

- 版本：v0.1
- 状态：生效
- 适用范围：本工作区的全部改动

## 1. 要解决的问题

AI 可以连续做很多步，但「做了什么、凭什么算完、谁确认过」经常只留在对话里，换一个会话就查不到。
本工作区把这三件事落成可查询的记录：**工单**记范围与验收条件，**尝试**记哪条会话在做，
**提交与验收**记成果、证据与结论。所有业务改动都经过同一条闭环。

## 2. 一条闭环的形状

```
create_ticket  → 建单，写清交付物与验收条件（每条附一条可跑的证据命令）
claim_ticket   → 协调会话落库派发意图，工单进 dispatching
bind_session   → 执行会话绑上自己的 session_id，工单进 running
submit_result  → 成果落库 + 摘要，工单进 awaiting_review
review_result  → 另一个会话逐项判定，进 done 或 rework
merge_ticket   → 合并后写回合并记录
```

顺序不能变，也不能合并成一次调用：中间的外部副作用（创建会话）不可回滚，必须落库之后再发生。

## 3. 必须成立的条件

- **归属不猜**：项目根目录来自宿主回执或人工选择，不从聊天语义推断。
- **版本可追**：每张工单记录 `prd_path` 与摘要；PRD 一改，基于旧版的成果报 `STALE_PRD`。
- **执行者不自验**：验收必须由没参与执行的另一个会话发起（`SELF_REVIEW` 会被拒）。
- **一次一张**：同项目默认只跑一张在途单；并行要显式声明。
- **收尾可判定**：一轮的结束由 `close_gate` 的退出码判定，不由一句话判定。

## 4. 验收条件

| 编号 | 条件 | 证据 |
| --- | --- | --- |
| AC1 | 空库能初始化并登记项目 | `python -m task_center --db <库> list_projects` 返回该项目 |
| AC2 | 一张单能从创建走到验收 | `get_ticket` 在 `submit_result` 后返回 `state=awaiting_review`，在 `review_result` 后返回 `done` |
| AC3 | 没工单的提交会被拦 | 不设 `TASK_CENTER_TICKET` 时 `git commit` 非零退出 |
| AC4 | 计划格式可校验 | `python tools/doc_gate.py --all` 退出 0 |
| AC5 | 一个轮次能收尾 | `python tools/close_gate.py` 退出 0 |

## 5. 不做什么

- 不替宿主创建会话：`claim` 之后的派发由协调会话调用宿主能力完成。
- 不做权限系统：闸门的目的是让「忘了开工单」当场失败，不是防止有意绕过。
- 不做看板与自动推进：进度以 `events` 与工单状态为准。
