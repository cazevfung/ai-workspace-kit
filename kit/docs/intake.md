# 交接协议（intake）

这是「别的项目的会话在做长线任务之前，怎么把事交给 {{WORKSPACE}}」的交接协议唯一正文。仓库外的会话读到它的固定路径是 `~/.agents/intake/intake.md`。安装时会把本目录复制到那里；工作区移动后重跑一次安装（或重新复制）即可，正文不用改。

## 1. 什么时候要交接

按顺序问三个问题，三个里有一个答案是「是」就交接：

1. 要不要拆成多步？
2. 要不要交付可验收的东西？
3. 一轮做不完吗？

## 2. 四行消息模板与六节交接包

**0.12（2026-11-18）起的口径**：交接消息是四行，背景由一份先落盘的六节交接包承担，不再只靠「对方去读原对话」。原来的三行模板作废。

交接消息写四行，不多不少：

```text
第 1 行：要做的事（一句话主题）。
第 2 行：这是从 <来源项目> 转来的长线任务，交给 {{WORKSPACE}} 的工单体系接手；来源会话标识：<session-id>。
第 3 行：交接包：<绝对路径>。六节齐全，缺节不得接收。
第 4 行：背景以交接包为准；历史可用 get_chat_history 按第 2 行的标识核对。
```

第 2 行里的来源项目有前提：原会话得真的绑着一个 Cindy 项目才这么写。原会话没有绑定项目时，不要写「从 <来源项目> 转来」——那会让人以为有个具体项目在等这件事；写成这是一个没有绑定项目的会话转来的，落点按 §7 选。第 2 行的会话标识原样写，不缩写、不从目录名拼。

### 2.1 六节交接包

包是 UTF-8 的 Markdown 文件，六节标题固定、顺序固定，标题文字不许改——闸门按这六行原样匹配，改一个字就是缺节。

| 节 | 内容 | 必填判据 |
| --- | --- | --- |
| `## 1. 用户原话` | 逐字引用，不改写、不摘要；与「重做、不满、必须保留」有关的句子一句都不能省 | 至少一段 `>` 引用块；缺引用即失败 |
| `## 2. 要交付什么` | 主题、形状、给谁看、什么算成功 | 非空 |
| `## 3. 做过什么、为什么不行` | 上一版做了什么、用户怎么评价、这次要改哪一层；没有前史就写「无前史」并说明依据 | 非空；不能只写「待补充」这类占位 |
| `## 4. 硬约束` | 不可改的工具、时长、风格、文件、口径；每条注明来自原话还是推断 | 非空 |
| `## 5. 已确认的事实` | 绝对路径、已跑过的命令与输出、版本号 | 至少一个绝对路径 |
| `## 6. 未决问题` | 问题—影响—选项；必须由人拍的标 `human` | 非空（没有就写「无」） |

为什么不再只写三行：三行版本把「补背景」整体托付给收件方去读原对话，而原对话里最容易丢的恰恰是判断类信息——用户说过「上一次哪里不行」「这次什么算好」「什么绝不能被改掉」。这些句子不像功能名那样有位置可放，于是最先被丢；丢完之后产物仍然能写得完备，验收也仍然能全绿。2026-11-18 的 1205 配乐交接就是这条路：收件方确实读了原对话，写出的 PRD 却只回答了文件层面的缺口。`tests/fixtures/intake/` 里留着那次事故的两份对照样本（旧的三行消息与按六节补齐的包）。

### 2.2 落点

- 来源会话绑着项目时：写到该项目里的 `交接/<YYYY-MM-DD>-<slug>.md`。
- 来源会话没有绑定项目时：写到 `{{WORKSPACE}}/.data/intake/<session-id>-<YYYY-MM-DD>.md`。

两种情况都把**绝对路径**写进消息第 3 行。交接包不进中心库，`submit_result` 的 `artifacts` 也不含它——它是文件层的协议，与工单状态机无关。

### 2.3 闸门与拒收

收件方（`{{WORKSPACE}}` 的协调会话）收到消息的第一件事是跑闸门，不是读 PRD：

```bash
python tools/intake_gate.py <交接包的绝对路径>
```

- **非零退出就是拒收。** 用 `send_to_session` 带 `target_session_id` 发回来源会话（不新建任务），消息只写缺哪一节与闸门输出；缺节退回补齐、不写 PRD、不开单。退回不占工单号，也不写事件。
- **通过之后还要抽查。** 脚本只保证「不空」，保证不了「不假」：来源会话完全可以写一份糊弄的包。协调会话要用 `get_chat_history` 按第 2 行的标识读一次原对话，抽查第 1 节有没有删减，并把抽查结论写进 PRD 的「需求来源（逐字）」节。两件事不能互相替代——闸门保证不空，抽查保证不假。
- **PRD 侧有落点。** PRD 必须有「需求来源（逐字）」一节，把交接包第 1、3 节原样搬进来（用 `python tools/intake_gate.py --extract <包>` 的输出，不手抄），第一条验收条件是「PRD 该节与交接包逐字一致」。这条让「用户的不满」从此有一条能被 diff 的位置。

## 3. 交接后不再推进

交接之后，原会话不许再推进同一件事；收到回执只向用户转述，不许再动手。这一条（交接后不再推进）是交接是否成立的判据。

## 4. 例外分支

已经在 `{{WORKSPACE}}` 里工作的会话就是协调者，不要向自己派发——否则会撞 `SELF_DISPATCH`。这条在提示词里也要有，防止协调会话自己触发交接。

## 5. 固定读取路径

固定读取路径就是 `~/.agents/intake/intake.md`，它是指向仓库 `docs/` 目录的 junction，仓库被移动后只需重建这一条链接。这个固定路径读到的是主检出（master）上的那份，分支上的修改要合并之后才能通过它看到。

## 6. 最终提示词文本

下面是可直接贴进 Cindy 自定义提示词的唯一权威文本，正文不超过 400 字符：

```text
在 {{WORKSPACE}} 之外的目录接到长线任务时（要拆成多步、要交付可验收的东西、一轮做不完——有一项就是）：先按固定读取路径 ~/.agents/intake/intake.md 的六节结构写交接包并落盘，取它的绝对路径；用 get_current_session_id 取自己的会话标识；用 send_to_session 新建 {{WORKSPACE}} 会话（不传 target_session_id，并显式传 project_path={{WORKSPACE}}——省略它会继承来源会话的归属），消息只写四行，第 3 行给交接包绝对路径；交接后不要再推进，收到回执只向用户转述。例外：已在 AI 工作区就不要发——你已是协调者。
```

这段文本里的「四行」指 §2 的模板；六节结构与闸门判据在 §2.1–§2.3，闸门脚本是 `python tools/intake_gate.py`。提示词只写指针，不重抄正文——正文随仓库走，提示词抄一份就会分叉。

## 7. 无项目会话的落点

来源会话没有绑定任何 Cindy 项目时，交接落在哪儿取决于原会话那一刻的状态：它空着，人可以把它整体搬过去；它正在跑，就只能另起一条。两条路径都先在目标目录上注册 Cindy 项目（`create_project` 只接受已存在的目录，不替你建目录），再按状态二选一：

- **路径①：原会话已空闲、且人确认要迁。** 用 `cindy_helper` 的 `move_session` 把原会话迁入目标项目，`project_path` 传注册回执里的那个路径。上下文跟着会话走，不用重建；迁完就在原会话里接着做，不另开一条。
- **路径②：原会话仍在跑。** 在目标项目新建会话接续：`send_to_session` 带 `project_path`，标题与正文写清工单号、attempt 与要做的事。新会话自己取 `session_id` 再 `bind_session`；原会话交接之后停手，回执到了只向用户转述。

**`move_session` 的限制，写在这里免得当它是万能的。先说清楚两件事别混：工具本身不要求确认，给 `session_id` 与 `working_dir` 就执行**——2026-11-17 对一个已空闲的本地会话直接调它，先迁入指定项目、再迁回原项目，两次都没有出现任何确认步骤，迁完消息数与对话内容不变。**「迁移前先问人」是我们自己的规矩，不是这个工具的前置条件**：同一个工具也能搬别人的会话，所以凡不是本会话自己的会话，迁移之前必须先经人同意；那一步没人拦你，只能自己守。工具这边剩下的限制是：只接受**空闲的本地任务**；明确拒绝移动正在运行的任务与正在调用它的那条任务；已归档、已删除、Bot 自有、Review 任务与 SSH 远程任务也移不了；它不搬项目文件、也不建任务。所以结论就一句——**空闲可迁、在途不能迁**：交接恰恰发生在源会话正推着一件事的时候，那一刻直接把它搬过去做不到，只能走路径②。
