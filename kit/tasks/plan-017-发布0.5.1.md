## 任务

### 一、工作树与尝试绑定

`git worktree add .worktrees/AWK-115 -b ticket/AWK-115 master`；会话标识用 `cindy_helper` 的 `call_tool` 调 `get_current_session_id` 现取，原样写进 `bind_session`，attempt 取 `get_ticket` 的 `current_attempt`。

证据：`git worktree list` 输出里出现 `.worktrees/AWK-115 ... [ticket/AWK-115]`；`get_ticket` 回执里 `state` 是 `running`。已跑，退出码 0。

### 二、版本号与三份文档同步

`VERSION` 写 `0.5.1`；`plugin/draft/ghost.json` 的 `"version"` 改 `0.5.1`（其余字段一个字节不动）；`CHANGELOG.md` 按交付物里的形状重排顶部；`README.md` / `README.en.md` 的 `0.5.0` → `0.5.1`、`1004` → `1012`、`ai-workspace-kit-0.5.0.cindy` → `ai-workspace-kit-0.5.1.cindy`。

证据：`cat VERSION` 输出 `0.5.1`；`python -c "import json;print(json.load(open('plugin/draft/ghost.json',encoding='utf-8'))['version'])"` 输出 `0.5.1`；`grep -n "## 0.5.1" CHANGELOG.md` 命中一行且该节正文含「安全修复」与「install」；`grep -c "未发布" CHANGELOG.md` 输出 `0`；`grep -rn "0\.5\.0" README.md README.en.md` 只剩描述历史的那一处（若仍有）、`grep -c "1012" README.md README.en.md` 各 ≥ 1。

### 三、重打包，`dist/` 只留一个包

`git rm dist/ai-workspace-kit-0.5.0.cindy`；`python tools/pack_plugin.py` 打 `dist/ai-workspace-kit-0.5.1.cindy`（时间戳固定、条目排序，同一份源码两次打出来字节相同）。宿主没有「打 `.cindy`」的能力，所以这条路本身就是可重复的手工方式，回执里写明命令。

证据：`python tools/test_plugin_pack.py` 退出码 0；`ls dist/*.cindy` 只列出 `dist/ai-workspace-kit-0.5.1.cindy`；`git status --short dist/` 只有「删除 0.5.0」与「新增 0.5.1」两条。

### 四、三道闸门全绿

在仓库根依次跑 `python tools/run_tests.py`、`python verify/verify_install.py`、`python maintainer/redact_for_public.py --check`；任一红就停在这里，不推。

证据：三条命令各自退出码 0；`run_tests.py` 末行 `结果：全部通过` 且汇总行合计 ≥ 1012；`verify_install.py` 末行 `<总数>/<总数> 项通过`；`redact_for_public.py --check` 无残留输出。

### 五、真装演练：沙箱装 0.5.1 不动真实 `~/.agents`

用打出来的包解到临时目录（或直接用仓库树），跑 `python install.py --workspace <临时>/ws --agents-home <临时>/agents --no-git`；装前装后各取一次真实 `~/.agents` 的快照（`kit/tools/install_guard.tree_digest`），并核对真实 `~/.agents/center.json` 的 `md5` 仍是 `c6e4b0b4d4e9a006fdb4b92f968ca650`；再跑一次 `--dry-run`，期望输出里有「跳过」与 `--allow-user-config` 且临时目录一个文件都没建。

证据：两次 `tree_digest` 相等（不等时打印差异路径）；`md5sum ~/.agents/center.json` 与基线相同；`--dry-run` 输出含「跳过」与 `--allow-user-config`，`<临时>/agents` 不存在；退出码 0。

### 六、推送、tag、Release

`git push origin master` → `git tag v0.5.1 && git push origin v0.5.1` → 源码包 `git archive --format=zip --prefix=ai-workspace-kit-0.5.1/ v0.5.1 -o dist/ai-workspace-kit-0.5.1-source.zip` → `gh release create v0.5.1 <两个资源> --title ... --notes ...`。note 里指回 `0.5.0`、写明安全修复与取代关系。**不推就一条都不推**：第 4 步任一红就停在这里。

证据：`git ls-remote --tags origin v0.5.1` 有输出且指向 `git rev-parse master` 同 sha；`git ls-remote --tags origin v0.5.0` 仍指向 `46ce67d`；`gh release view v0.5.1 --json assets --jq '.assets[].name'` 输出两行 `ai-workspace-kit-0.5.1.cindy` 与 `ai-workspace-kit-0.5.1-source.zip`。

### 七、提交成果与回执

`submit_result`：artifacts 路径带 `.worktrees/AWK-115/` 前缀，`head_sha` 取本次 `git rev-parse HEAD`，`evidence` 逐条贴上面各任务的命令与输出摘要；随后按 `ticket-dispatch` 的口径给协调会话发**一条**回执：工单号 + 状态 + tag + Release 地址。

证据：`submit_result` 回执 `ok=true`、工单进 `awaiting_review`；回执消息只发一条，正文含 `AWK-115`、`v0.5.1` 与 Release URL。
