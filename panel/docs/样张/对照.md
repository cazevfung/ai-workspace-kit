# 420×700 浮窗：整卡（A）与折叠（B）对照

同一份 `sample.html`、同一套 token、同一份数据；差别只有「一屏先给你看什么」。

- **A 整卡**（默认）：`docs/样张/浮窗-浅色.png`、`浮窗-深色.png`
- **B 折叠**：`docs/样张/浮窗-折叠-浅色.png`、`浮窗-折叠-深色.png`
- 切法：URL 加 `?view=folded`（原来右上角那颗「折叠 / 整卡」按钮在 CD-017 里去掉了——那两位被换成
  只留一颗「整体收成一行」的箭头按钮）；可以和 `?source=export` 叠加，真数据下同样生效。

## 一屏各看到什么（420×700，DPR 1）

| | A 整卡 | B 折叠 |
| --- | --- | --- |
| 首屏项目数 | **1 个**（第一张卡实测高 670px，第二张要滚） | **5 个**（5 行，每行 62px + 卡间 16px，全部在一屏内） |
| 一眼能答的问题 | 这个项目里，每条单停在第几步 | 哪几个项目在等我、各几件 |
| 第二三个项目的「需要你出手／待验收」 | 被第一张卡挡在屏幕外 | 5 行里 3 行带橙点，一眼看全 |
| 行尾 184／轨道／呼吸 800ms·1.18／四态颜色 | 有 | 折叠时不出现；点开就是同一张卡 |

数一下：A 首屏 `cindy-dashboard` 一张卡；B 首屏 `cindy-dashboard / Cindy鸿蒙客户端 / AI工作区 / ai-workspace-kit / 1205经营季前瞻` 五行。
真实导出（`?source=export`）里同样是 5 个项目、5 行。

## B 把什么收起来了

折叠行只有三样：**项目名 · 状态点 · 一句计数**，其余全部要**点这一行**才出现（原地展开成 A 的整卡，不跳页）：

- 主任务标题与它的 message 图标；
- 每条单的单号、标题、五步轨道、resolve 与进会话两枚图标；
- 「已在 master 里，但库里没有合并记录」这类合并说明；
- 「还没人认领」那一块与卡内三处折叠（主任务 3 个、更早的单、池子 2 条）。

换句话说：**B 只回答「哪个项目要你」，A 才回答「哪张单在哪一步」**。B 是入口，不是替代。

## 状态点与那一句计数

- 橙点 = `待验收 N` / `需要你出手 N`——和 A 卡头的点与数字**同一句**，两个视图不会说两套数。
- 中性点 = 这个项目没有待验收、也没有需要你出手的事，后面跟的是这张卡的总张数（`N 张单`）。
- 橙色仍然只出现在那两处（当前步、需要你出手／待验收的状态点）；中性点用的是中性色。

## 交互与代价

- 点一行 → 原地展开成整卡；点卡头（展开后右上角多一个「收起」）→ 折回一行。
- 数据每 3 秒刷新时，已展开的项目保持展开（按项目名记）；但**整页刷新会回到全折叠**。
- 折叠视图没有单独的存储：它只是同一个页面的另一种视图，数据层（`exportfeed` / `/api/feed`）没有任何差别。

## 怎么选（不替人拍板）

- 先要「哪个项目在等我」→ B（一屏看全，点开看细节）。
- 先要「哪张单停在哪一步」→ A（默认，已验收过的那一版）。
- 也可以两个都留：默认 A，需要扫一眼全项目时切 B。切换不丢数据、不改任何视觉 token。
