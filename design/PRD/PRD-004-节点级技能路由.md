## 1. 要解决什么问题

用户的原话是「工作区在每个需要判断的节点都能调到合适的 skill」。现状是做不到，原因不是 skill 不够，是**入口只有一处**：

- 全工作区唯一的路由器是 `.agents/skills/plan-gate/SKILL.md` 里的那张表，而它只在「做规划之前」被触发。
- 执行会话与验收会话没有任何等价入口。它们会不会读到合适的 skill，取决于那个会话恰好有没有读 `AGENTS.md`——这不是取舍，是入口缺失。
- 本机已装 30 余个 skill，其中 6 个装了没有出现在任何路由里（`systematic-debugging`、`merge-latest-branches`、`shuo-ren-hua`、`dispatching-parallel-agents`、`subagent-driven-development`、`resumable-implementation-contracts`）。「装了」等于「不会自动加载」。
- 没有任何机制能发现「已装的 skill 没接」或「路由表里写了一个不存在的 skill」。`plan-gate` 点名的 skill 名靠 `tools/doc_gate.py` 查真实性，但那只在写计划时查，不是全局覆盖。

上一轮盘点给出 28 个判断节点（用户口述 27，差异在 N25「新建或修改 skill 本身」是否算判断节点；本轮按 28 计，包含它）。按附录 A 逐条数下来是：15 个已接入、3 个只覆盖一半（N05/N17/N18）、4 个节点上装了 skill 却没接（N15/N22/N26/N27，共 6 个 skill）、6 个没有任何 skill（N02/N03/N06/N12/N23/N24）。首版这里写的是「6 个装了没接、7 个没有 skill」，那是把 skill 个数与节点个数混在一起数错了，v0.2 改正。**v0.3 加了一个节点 N29，总数到 29；0.5 再加 N30，现在总数是 30 个；0.6 再加 N31，现在总数是 31 个，其中没有 skill 的是 8 个（N02/N03/N06/N12/N23/N24/N29/N31）**——N29 管「把一条消息送进一个正在跑的会话：投进去还是插进这一轮，发完怎么确认打中了原目标」，归口是一条动作，判据在 `PRD-005` §8，不另开 skill（理由写在 `gaps.md`）；N30 管「共用可变资源的身份与占用：取证前先核、证据带身份、变了作废、占用要归还」，0.5 起归口到新 skill `shared-resource-identity`，口径与 AC 在 `PRD/PRD-012-共用资源的身份与占用.md`；N31 管「干活时发现了一个不属于本单的问题：它落在哪个项目的哪张单」，0.6 起归口成一条当场可执行的动作（当场 `create_ticket`、`state=planned`、不 claim 不派发不 bind），理由同样写在 `gaps.md`。清单见附录 A——它是本 PRD 的一部分，不是参考材料：总表就是按它建，验收也按它数。

## 2. 边界：这一版只做路由，不造方法

| 做 | 不做 |
| --- | --- |
| 一张覆盖 31 个节点的总表，每行给归口 | 不为缺口节点新写方法类 skill |
| 协调 / 执行 / 验收三类会话各一张最小入口表 | 不改 `plan-gate` `pdsa-workflow` `prd-authoring` `ticket-dispatch` 的正文 |
| 一个能反向发现「装了没接」的校验脚本 | 不碰 `AGENTS.md`（等 AW-018 合完另开单） |
| 缺口节点给确定性兜底动作（脚本命令或一句话规则） | 不碰 `task_center/`、`tools/` |

缺口节点写「无 skill，兜底动作是 X」，不许为了表格好看编一个 skill 名顶上。`plan-gate` 已经把「点个名假装用了」定成反模式，这里同样成立。

## 3. 角色分工

- 协调会话：写本 PRD（需求），开单、派发、收口、报回执。不产出路由表。
- 执行会话：产出路由层全部文件，自检后 `submit_result`。
- 验收会话：另一个未参与执行的会话，逐项对照 AC 与文件本身判定。
- 三者都不修改本 PRD。

## 4. 需求条目

**R1 节点总表。** 31 个节点每个都要有唯一编号与归口。归口只有两种合法形态：一个**真实存在**的 skill 名（在本仓库 `.agents/skills/` 或本机 `~/.agents/skills/` 里能找到 `SKILL.md`），或一条**可执行/可判定**的兜底动作（脚本命令、或一句话规则）。禁止空白归口，禁止自造 skill 名。

**R2 三类入口。** 协调、执行、验收各一张表，只列该角色会命中的节点，并给出该角色的第一条动作。任何一张表里出现的节点编号必须在总表中存在。

**R3 反向覆盖。** 本机已装 skill 的完整清单（本仓库 4 个 + `~/.agents/skills/` 下全部）都要有处置：接入某节点，或列入「明确不接」并写明它属于哪个项目面（例如内容生产、公司事务、业务平台）。「已装且未处置」必须被判为错误，不许沉默。

**R4 缺口清单。** 没有任何 skill 可归口的节点单独列出，写清兜底动作是什么、以及为什么这轮不新建 skill。

**R5 校验脚本。** 一个脚本，至少能对四类错误各自返回非零并指出位置：skill 名不存在；节点缺归口；已装 skill 未被处置；角色表引用了不存在的节点编号。正确输入退出 0。

**R6 脚本自身的证据。** 脚本必须有反例用例：逐个制造上述四类错误，证明每一条检查真的会失败（不是写了没生效）。正例与反例都要能一条命令跑完。

**R7 入口可发现。** 入口文件的 frontmatter `description` 要能让任意会话在「开始工作」和「遇到判断点」时命中它，而不只是「写计划之前」。这是本 PRD 唯一的可发现性杠杆——`AGENTS.md` 这轮不能动，所以入口只能靠 description 和文件自身站立。
