# PRD-003：全局项目定位与派发入口

- 状态：已实现并通过本机验证，等待真实多会话试用
- 版本：0.2
- 日期：2026-11-17
- 所属项目：{{WORKSPACE}}（代码仓库），能力本身是 Cindy 全局的
- 依据：PRD-001 v0.6 §4（四类会话分工）、§5（项目上下文如何加载）、§7（项目记录）、AC02

## 1. 为什么要改

PRD-002 把项目定位做成 `task_center/probe.py`，放在 AI 工作区这个项目里，由协调会话主动调用。它在自己的场景里是通的，但有个定位错误：**它是一件基础设施，却放在一个业务项目目录里。**

后果很具体：只有从 `{{WORKSPACE}}` 起手的会话才用得到它。从任意别的目录开一个 chat，这个能力等于不存在。而 PRD-001 §1 一开始要的就是"AI 能持续推进"，用户后来把这句话说得更清楚——**随便开一个 chat 也要能按整套机制走**。

## 2. 边界：定位全局化，推进不全局化

| 问题 | 归属 | 有无状态 |
| --- | --- | --- |
| 这段对话属于哪个项目 / 目录 | Cindy 全局能力 | 无。每次现算，答错代价是多问一句 |
| 做到哪一步、依据哪版需求、谁验收 | 中心库（仍在 AI 工作区） | 有。必须跨会话恢复 |

推进不能跟着全局化：若每台机器只有一个全局工单池，所有项目共用一个进度，"PRD 与成果留在业务项目"和 AC02 的项目隔离都会破。

**§4 的四类会话分工不变**：协调、规划、执行、验收仍分开，执行者不得验收自己的工单。变的只有"必须从 AI 工作区出发"这一条限制——取消。

## 3. 三个组件

| 组件 | 位置 | 作用 |
| --- | --- | --- |
| 技能 | `~/.agents/skills/project-routing/SKILL.md` | 一页规则：先信你已经在的地方 → 再看本地事实 → 最后问 |
| 脚本 | 同目录 `scripts/probe.py` | 只读探针，零参数可用；仓库 `task_center/probe.py` 是可测试源文件 |
| 中心位置 | `~/.agents/center.json` 的 `db` 字段 | 一处常量，不散落在会话指令里 |

技能与脚本都在仓库之外，因此不受仓库分支状态影响；脚本需要从仓库同步，命令写在技能里。

## 4. 默认值就是架构

全局化的实质不是加功能，是改默认值：

| 参数 | 改前 | 改后 |
| --- | --- | --- |
| 起点 | `--roots` 必填 | 当前目录，零参数 |
| 扫描 | 每次必扫 | **默认不扫**，给 `--roots` 才扫 |
| 中心库 | `--db` 必填 | 读配置文件，`--db` 可覆盖 |
| 输出 | 完整报告 3933 字节 | 摘要 486 字节，`--full` 才完整 |

一个 chat 已经在某个目录里，答案就在那儿。扫描只用于"你没站在任何项目里，但想指定一个"。

## 5. 识别顺序

1. 会话的 working_dir / 宿主回执的 `project_path` —— 有就直接用，零成本。
2. 话里有项目名或路径 —— 精确命中直接用；互为前缀（`X` 与 `X-2`）算歧义，并列。
3. 以上都没有 —— 跑探针，看 `here.registered`。
4. `here.root` 为空或对不上 —— **问**，列 2–3 个带路径的选项。
5. 任何一步都不得挑"最近活跃的"顶替一个对不上的项目。

三条硬规则（沿用 PRD-002 AC10/AC11 并补充）：

- 未注册的目录只能提议注册，不能在上面派发。
- 与项目无关的请求不硬塞进项目。
- 执行与验收必须是不同会话；核心以 `SELF_REVIEW` 拒绝自验收。

## 7. 已知缺口

1. `bind_session` 的会话标识仍是自报字符串，`host_identity_verified` 恒为 false。真实回执适配属 PRD-001 §9 与 §15，不在本 PRD。
2. 宿主会话历史（这台机器跑过哪些目录）还没接入，目前 `near` 只能靠 `--roots` 扫描得到。
3. 命中记录（PRD-002 §10 唯一的自演化点）仍未实现，"越用越省"仍属推断。
4. **已补（`unregister_project`）**：撤销错误登记，有工单时返回 `PROJECT_HAS_TICKETS` 并列出工单。仍未改的是 `projects.root`：修正路径要「撤销→重登记」。`list_projects` 同时补上，项目清单不再只能读库或靠工单反推。
5. 扫描根配置本身仍会衰减（用户搬目录后不更新），只能靠 `--explain` 发现。

## 8. 验收条件

- AC01：任意目录、零参数运行可回答"我在哪"，且默认不扫描磁盘。（已验证）
- AC02：`here.registered` 能识别"git 根比注册根更深"的情况，并保留两个事实。（已验证）
- AC03：中心库只能被发现，不能被新建；找不到时报告原因。（已验证）
- AC04：摘要体积不超过完整报告的一半。（已验证）
- AC05：任意会话在不写死路径的情况下可完成 create/claim/bind。（已验证，一次性库）
- AC06：话里对不上任何项目时必须提问，不得以最近活跃项顶替。（规则已定，未自动化）
- AC07：执行者自验收被拒绝。（沿用核心既有测试）
- AC08：登记错了可撤销，且有工单时拒绝撤销。（已验证：`tests/test_projects.py` 5 项，含撤销后同路径可重登记、拒绝时回执列出工单）

## 9. 与既有 PRD 的关系

- PRD-001：§4 分工不变；§5"不凭聊天语义猜测项目归属"仍然有效，本 PRD 补的是"不猜之后从哪拿事实"。§14 提到候选层"`SCHEMA_VERSION` 保持 2"已被 schema 3 取代，属过期描述。
